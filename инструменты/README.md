# Служебные скрипты курса

В сборку `Тетрадь аналитика.html` не входят. Нужны, чтобы проверять
числа в уроках и пересобирать данные.

| Файл | Зачем |
|---|---|
| `gen_app.py` | Генератор журнала приложения для модуля 4 (4000 установок, 28 567 дней активности, 2027 заказов). Печатает контрольные срезы: удержание по когортам, доли каналов, деньги. |
| `emit_app.py` | Выгружает результат генератора в три CSV. Их содержимое вставлено в `data.js` как `appUsersCSV`, `appActivityCSV`, `appOrdersCSV`. |
| `balance_quiz.py` | Перемешивает варианты ответов в квизах и раскладывает верный по позициям равномерно. Запуск: `python3 balance_quiz.py ../content-m5.js`. |
| `mkdb.py` | Собирает `shop.db` из `data.js` и `data-taxi.js` — база для локальной проверки SQL-задач; и `vilka.db` из `data-vilka.js` (модуль 7): без первичных ключей, как после `to_sql` в Colab, — дубли выгрузки остаются. |
| `appprelude.py` | Пролог python-уроков модуля 4 для локального прогона: читает CSV прямо из `data.js`. |
| `runpy.js` | Достаёт из урока решение, эталон или код тренажёра. `node runpy.js m4l4 expected`. |
| `checksql.js`, `drillsql.js` | То же для SQL-уроков и их тренажёров. |
| `checkdrills.js` | Код эталона каждой задачи тренажёра с автопроверкой выполняется (SQL на `shop.db`) или хотя бы разбирается (Python). Та же классификация, что у `Drills` в `app.js`. |
| `figs.py m1 [--check]` | Генерирует SVG-схемы теории модуля (стиль «Тетрадь», числа из `shop.db`) в блок `FIGS` файла `content-m1.js`; `--check` только сверяет числа схем с базой. |
| `checkfigs.js` | Схемы в теории: каждая метка `data-fig` указывает на схему и каждая схема где-то стоит, есть `role="img"`, `<title>` и `<desc>`, ширина `viewBox` ≤ 340, цвета только классами `.f-*`. |
| `gen_taxi.py [--check]` | Генератор базы «Дельта Такси» (урок 6.4): зерно 2024, только `random.Random` — побайтно тот же `data-taxi.js`. Печатает контрольные числа: статусы, доля «нет машины» и подача по городам и полугодиям, поездки и наценка по часам. `--check` сверяет файл с генератором. |
| `gen_vilka.py [--check]` | Генератор базы «Вилка» (модуль 7): зерно 2025, только `random.Random` — побайтно тот же `data-vilka.js`. Печатает контрольные числа: дубли, internal, группы эксперимента, конверсия и выручка на пользователя. `--check` сверяет файл с генератором. |
| `checktaxi.js` | Такси: строк в `data-taxi.js` столько же, сколько в `shop.db`; сценарии `Taxi.wants` из `app.js` (какой запрос подгружает такси). |
| `mkxlsx.py [--check]` | Собирает три книги: из `data.js` — `delta-market.xlsx` (урок 6.6) — листы orders, users, leads; `app-journal.xlsx` (урок 4.7) — листы app_users, app_activity, app_orders; из `data-vilka.js` — `vilka.xlsx` (модуль 7): customers, restaurants, orders, experiment; даты — датами Excel. Сборка повторяемая (даты внутри zip и в свойствах книги фиксированы); `--check` сверяет распакованные листы с файлами в ветке. Нужен openpyxl 3.1.5. |
| `checknums.js` | Поля для чисел: сценарии разбора ввода (`Nums` вырезается из `app.js`) и эталоны — у каждого поля урока `sheet` и задачи `answer: "nums"` запрос `check` на `shop.db` (у урока с `db: "vilka"` — на `vilka.db`) даёт `answer` ± `tol`; поле с `py: true` (p-value; только в задаче урока с `VILKA_CODE`, с `tol` < 1, без `check`) сверяет `checkvilka.py`; урок с `ready: true` без содержимого — ошибка; указанный в уроке `file` должен быть на диске. |
| `checkvilka.py [python]` | Прогоняет эталонный код модуля 7 (`window.VILKA_CODE` в `content-m7.js`: загрузка + чистка + код этапа) на копии `vilka.xlsx` и сверяет напечатанные числа с `answer ± tol` полей урока. На pandas 2.2: `python3 инструменты/checkvilka.py ~/.cache/analyst-notebook/v312/bin/python`. |
| `checkcheats.js` | Шпаргалки (`cheats.js`): SQL-примеры выполняются на `shop.db` и что-то возвращают, Python-примеры идут подряд после пролога Python-уроков на python3 и на pandas 2.2 из `~/.cache/analyst-notebook`, если оно есть; поля и модули шпаргалок на месте. |
| `checkorder.js` | Ключи прогресса не сдвинулись относительно `origin/main`: все `id` уроков на месте, в `steps`, `practicum.steps`, `cards`, `quiz`, `drills` нет вставок и удалений в середине. Правку текста на прежнем месте только перечисляет. Запускается из `ci.sh` и хуком Claude Code после правки `content-m*.js`. |
| `release.sh` | Выпуск ветки: новая `VERSION` (дата и следующая буква после версии в main), сборка офлайн-файла, коммит «<что>: выпуск <версия>», `ci.sh`. Не работает на main, на слитой ветке, с незакоммиченными правками и при другом открытом PR с `sw.js`. `bash release.sh --dry-run` — только проверить и посчитать версию. |
| `devserver.py` | Сайт без кэша для разработки; `/__mtime` — время последней правки файлов сайта, по нему проверка в браузере понимает, что страница устарела. |
| `ci.sh` | Все проверки разом — то же, что GitHub запускает на каждом PR (`.github/workflows/check.yml`): синтаксис, тренажёр, карточки, словарь, шаги уроков, порядок шагов, схемы и их числа, «всё пересобрано» (схемы и офлайн-файл), поднята ли `VERSION`. `bash инструменты/ci.sh`. |

## Шпаргалки

Код в `cheats.js` проверяет `checkcheats.js` (он же шаг в `ci.sh`), а вот
то, что лист по-прежнему один, — только печатью. После правки текста или
стилей печати откройте каждую `#cheat-<id>` на devserver, «Распечатать или
сохранить в PDF», формат A4: в предпросмотре должна быть одна страница.
Строка кода длиннее ~54 знаков на бумаге переносится — лучше разбить её
самому.

## Порядок проверки урока

    python3 инструменты/mkdb.py                       # если менялись данные
    node инструменты/runpy.js m4l4 > /tmp/sol.py
    cat инструменты/appprelude.py /tmp/sol.py | python3 -   # сверить с эталоном

После записи текста в `content-*.js` — проверка на посторонние символы:

    python3 -c "import pathlib,sys; s=pathlib.Path(sys.argv[1]).read_text(encoding='utf-8'); print(sorted({c for c in s if 0x2E00 < ord(c) < 0xFF00}))" content-m5.js
