# Практикум к уроку

Практикум — 5–9 шагов между карточками и основной задачей урока: в каждом
одна новая конструкция, таблица «было → стало» на настоящих строках базы и
маленький код, который курс проверяет сам. Формат полей — в `README.md`,
раздел «Как добавить практикум в обычный урок». Урок: `$ARGUMENTS`.

## 1. Прочитать урок и найти обрывы

- Прочитать теорию, тикет, схему, пролог, решение основной задачи и тренажёр урока.
- Прогнать аудит пути ученика — что урок требует раньше, чем объясняет:

      python3 .claude/skills/new-practicum/scripts/audit.py m3   # префикс модуля

  Обрывы в основной задаче закрывает практикум; обрывы в тренажёре — строка
  `<p><strong>Пригодится.</strong> …</p>` в конце `body` задачи.

## 2. Спроектировать шаги

- **Практикум не решает основную задачу.** Шаги идут на других данных или
  другом разрезе: другой канал, месяцы вместо недель, сделки из лидов вместо
  заказов. Числа основной задачи в шагах не появляются.
- Каждый шаг — одна новая мысль. Если действий больше одного — список
  `<ol class="order">` под заголовком «Порядок действий».
- Шаги строят то, что понадобится в задаче, в её же порядке. Последний шаг
  часто — «собрать в функцию» или «напечатать отчёт строками».
- `done` — что из шагов собирает задача и что в ней новое (об этом — подсказки).
- Заготовка каждого шага **не должна** проходить проверку; каждый шаг
  запускается в чистом пространстве имён, поэтому заготовка повторяет нужное
  из прошлых шагов.
- Для SQL `expected: { ordered, columns, rows }`, для Python `expected: { stdout }`,
  для графиков `expected: { plot: "…" }` (в `packages` практикума — `matplotlib`).

## 3. Посчитать числа

Каждое число в тексте, таблицах «было → стало» и эталонах — из запуска, не из головы.

- SQL: учебная база из `data.js` (рецепт в `ПРОГРЕСС.md`) или
  `node инструменты/checksteps.js <id> --try <шаг> "<SQL>"`.
- Python — в двух версиях pandas: локальной 3.x и 2.2, как в браузере:

      bash .claude/skills/new-practicum/scripts/setup-pandas22.sh <scratchpad>

## 4. Подводные камни, на которых уже спотыкались

- Текстовые Series не печатать (`print(df["source"])`): подпись dtype в
  pandas 2 — `object`, в 3 — `str`. Печатать таблицы, числа, `.tolist()`.
- Числа с пятёркой в третьем знаке (24790.405) при `:.2f` печатаются спорно —
  менять формат или данные.
- Код шагов живёт в строках JS: в шаблонных строках `\n` внутри питоновского
  кода становится переносом — писать `splitlines()` или `\\n`; в строках в
  двойных кавычках переносы — `\n`, кавычки — `\"`.
- В SQLite имя столбца из `SELECT` не видно внутри `OVER (ORDER BY …)` —
  повторять выражение.
- Бесконечный `while` в браузере вешает Pyodide — в шагах с циклами давать
  подсказку про изменение счётчика.
- Новая частая ошибка ученика — правило в `Check.pyErr` в `app.js`.
- Заодно проверять, что код из теории урока работает на данных курса (в 2.4
  пример среза падал на неотсортированном индексе).

## 5. Вставить и проверить

- Практикум — поле `practicum` в объекте урока, между `prelude` и `starter`.
  В `plan` урока строка «Практикум: N шагов …», `duration` +30 минут.
- Проверки:

      node инструменты/checksteps.js <id>
      python3 .claude/skills/new-practicum/scripts/practicum_check.py <id>
      python3 .claude/skills/new-practicum/scripts/practicum_check.py <id> --python <scratchpad>/v312/bin/python

- Браузер: `python3 инструменты/devserver.py 8781` (фоном), страница
  `http://localhost:8781/index.html#<id>`, `browser_resize` 390×844, затем
  `browser_evaluate` с текстом `scripts/browser-check.js`, где `LESSON_ID`
  заменён на id урока. Ждём: у каждого шага заготовка «Пока не совпадает»,
  решение `passed`, основная задача «Задание выполнено», `pageW` и
  `maxRight` не больше 390.
- В README дописать урок в список «сейчас он есть в …».
- Перед PR — агент `lesson-reviewer`; для нового материала для новичков —
  ещё и `student-walkthrough`.

Коммит содержания — один; выпуск (версия, сборка, PR) — скилл `/release`.
