# Схемы для модуля

Что рисуем: $ARGUMENTS

Одна схема — это агент `figure-builder` (`.claude/agents/figure-builder.md`,
там стиль, проверки и просмотр в браузере). Этот скилл — работа вокруг
него: выбрать места, не выдать ответы, не сломать чужие схемы, выпустить.
Так сделаны модуль 0 (#87) и модуль 7 (#88).

## 1. Что уже есть

    grep -o 'data-fig="[^"]*"' content-mN.js            # схемы модуля
    grep -n '^FIGS_M\|^MODULES' инструменты/figs.py    # модули в figs.py

Посмотри схемы соседних модулей на ту же тему (`grep data-fig content-m*.js`)
— новая не должна повторять готовую: например, «решение в первом абзаце»
уже нарисовано в `answer-first` (4.7), groupby — в `groupby-sac` (2.1).

## 2. Где схема и на чём

Прочитай теорию каждого урока (в модуле 0 — `body` шагов) и найди место,
где главная мысль держится только на тексте. Одна схема на урок; урок
без такой мысли — без схемы.

Потом выпиши ответы, которые схема не должна показывать:

    node .claude/skills/module-figures/scripts/answers.js mN      # весь модуль
    node .claude/skills/module-figures/scripts/answers.js mNlK    # один урок

Скрипт печатает `expected` шагов, `answer:` полей и тренажёров и числа из
`hint` (там неверные значения при типичной ошибке). Правила выбора данных:

- Число из теории урока показывать можно. Число-ответ — нельзя, даже если
  схема про другое.
- Пример теории совпадает с задачей шага — те же действия на других
  данных: другой клиент, другой столбец, другой месяц (так сделаны
  `group-collapse`, `inside-out`, `loop-trace` в m0).
- «Водопад» от грязного к чистому почти всегда раскрывает ответы чистки —
  лучше настоящий маленький кусок строк.

Покажи владельцу таблицу «урок · схема · что показывает · откуда числа» и
что останется без схемы и почему. Рисовать — после его «да».

## 3. Ветка и заготовка

Ветка от свежего `main` (хук не даст править на `main`). Если модуля нет
в `MODULES`, заведи раздел перед `MODULES`:

    FIGS_MN = {
    }


    def check_mN():
        return []

и `"mN": (FIGS_MN, check_mN, {})` в `MODULES`. База — `db()` (`shop.db`) или
`vdb()` (`vilka.db`, модуль 7). Проверка: `python3 инструменты/figs.py mN --check`.
В модуле без блока теории (m0) схемы стоят в `body` шагов — движок
(`Figs.mount` в шагах) и `checkfigs.js` это уже умеют.

## 4. Схемы — по одной, по очереди

Агенты `figure-builder` запускай **последовательно**, не параллельно: все
правят `figs.py` и `content-mN.js`. В задании агенту:

- урок, место метки, мысль схемы и откуда числа;
- список ответов урока из шага 2 — «не показывать»;
- что уже сделано в этой ветке (образцы — предыдущие схемы).

После каждого агента сам посмотри скриншот (`Read` по пути из отчёта) и
поправь мелочи сразу: подпись, место метки, заметку. Если агент отступил
от согласованного (взял другие данные) — проверь причину; разумную
замену прими и скажи владельцу.

## 5. Проверки

    python3 инструменты/figs.py --render-all     # все схемы всех модулей рисуются
    node инструменты/checkfigs.js                 # метки, подписи, диктор, цвета
    node инструменты/checkorder.js
    bash инструменты/ci.sh

До коммита выпуска в `ci.sh` красные только «Всё пересобрано» и «Версия
сайта»; шаг «Схемы рисуются» должен быть зелёным. Затем ревью
`lesson-reviewer` (числа, ответы, тон); если менялся движок — ещё
`engine-reviewer`. Для m0 — проверка в браузере: схема в открытом шаге и
при раскрытии пройденного.

## 6. Выпуск

Владельцу — таблица схем, отступления от согласованного, что сказали
ревью. После его «Давай»: коммит содержания, затем `/release` (или
`bash инструменты/release.sh "Схемы модуля N" --trailer "…"`), PR в `main`
и команды `gh pr checks` / `gh pr merge` для владельца.
