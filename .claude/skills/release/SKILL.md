# Выпуск ветки

Выпускаем: $ARGUMENTS. Содержание уже закоммичено в текущей ветке одним или
несколькими коммитами; здесь — только выпуск. Механику выпуска делает
`инструменты/release.sh` — его же Claude запускает сам, когда владелец
согласился на выпуск в разговоре.

1. **README до выпуска.** Если выпускается практикум — урок должен быть в
   списке «сейчас он есть в …». Правка README идёт в коммит содержания:
   скрипт откажется работать с незакоммиченными правками.
2. **Проверить готовность:** `bash инструменты/release.sh --dry-run`. Скрипт
   скажет, на какой версии остановится, и откажется, если ветка — main или
   уже слита, если есть незакоммиченные правки или открыт другой PR с `sw.js`.
3. **Выпуск** — каждая строка подписи из системных указаний своим
   `--trailer`:

       bash инструменты/release.sh "<что>" --trailer "Co-Authored-By: …" --trailer "…"

   Скрипт переносит ветку на свежий origin/main (если её ещё нет на
   GitHub; свой прошлый коммит выпуска при этом убирает и собирает заново),
   ставит `VERSION` — сегодняшняя дата и следующая буква после версии в
   main, в новый день `a`, — собирает офлайн-файл, коммитит «<что>: выпуск
   <версия>» и гоняет `ci.sh`. Повторный запуск в тот же день версию не
   сдвигает. Упал `ci.sh` или нужна правка после выпуска — поправить
   коммитом содержания и запустить выпуск ещё раз: появится второй коммит
   «выпуск», это допустимо.
4. **PR в main**, не стопкой: `git push -u origin <ветка>`, затем
   `gh pr create --base main`. В описании: что сделано по шагам, числа,
   находки по дороге, `VERSION`, чем проверено; в конце — подпись из
   системных указаний.
5. **Отдать владельцу команды слияния** — он просил давать их каждый раз:

       gh pr checks N --watch -R nekozlovskiy/analyst-notebook
       gh pr merge N --merge -R nekozlovskiy/analyst-notebook
