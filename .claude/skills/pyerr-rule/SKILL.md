# Новое правило в Check.pyErr

Ошибка: $ARGUMENTS

`Check.pyErr(msg)` в `app.js` берёт последнюю строку трассировки и по
регулярным выражениям подбирает подсказку. Правила проверяются **сверху
вниз, срабатывает первое** — поэтому частные случаи стоят выше общих
(`KeyError: … non-monotonic` выше `KeyError: '…'`, все `NameError` выше
`SyntaxError`).

## 1. Увидеть, что ученик получает сейчас

    node .claude/skills/pyerr-rule/scripts/try-pyerr.js "<последняя строка ошибки>"
    node .claude/skills/pyerr-rule/scripts/try-pyerr.js --code "<код ученика>"
    node .claude/skills/pyerr-rule/scripts/try-pyerr.js --list   # правила по порядку

Текст ошибки берите настоящий, из запуска. В браузере Python 3.12 и
pandas 2.2 (Pyodide 0.26) — их сообщения бывают другими, чем у локальных
Python 3.13+ и pandas 3. Проверьте обе версии:

    bash .claude/skills/new-practicum/scripts/setup-pandas22.sh <scratchpad>/py22
    node .claude/skills/pyerr-rule/scripts/try-pyerr.js --code "…" --python <scratchpad>/py22/v312/bin/python

Если подсказка уже есть и она верна — правило не нужно. Если есть, но
вводит в заблуждение, — поправить её или поставить частное правило выше.

## 2. Написать правило

- Регулярное выражение по последней строке (`last`), по возможности без
  номеров строк и имён переменных ученика — они меняются. Оно должно
  совпадать с сообщениями и pandas 2.2, и pandas 3.
- Место в списке: выше любого более общего правила, которое иначе
  сработает раньше. После вставки `--list` показывает итоговый порядок.
- Имя из ошибки можно вставить в текст через `exec` и группу, как у
  `NameError` и `KeyError`.
- Текст подсказки — тон курса: без восклицаний, на «вы», одна-две фразы.
  Сначала что сломалось, потом что поправить, с примером кода в том виде,
  в каком его пишут в уроках (`ascending=False`, `таблица[["a", "b"]]`).
  Не обещать, что это единственная причина, если их несколько.

## 3. Проверить

- `try-pyerr.js` на новой ошибке в pandas 2.2 и локальной версии —
  новая подсказка.
- Прогнать `try-pyerr.js` на последних строках соседних правил
  (тех, что теперь стоят ниже нового): их подсказки не изменились.
- `node --check app.js` (делает и хук), затем `bash инструменты/ci.sh`.
- `app.js` — файл сайта: при выпуске нужна новая `VERSION` в `sw.js`
  (это делает `/release`).
