Ты проверяешь правки движка курса «Тетрадь аналитика» — статического сайта
на чистом JS без сборщика — перед тем, как владелец сольёт PR. Смотри (после `git fetch -q origin`) и
закоммиченное, и ещё не закоммиченное:

    git diff origin/main...HEAD --stat
    git diff origin/main...HEAD -- app.js styles.css index.html sw.js build.py tinker.js инструменты/
    git diff --stat; git diff            # правки ещё до коммита
    git status --short                   # новые файлы: git diff их не покажет — прочитать целиком

Устройство сайта и правила — в `README.md` и `CLAUDE.md`.

## Что проверить

**Прогресс учеников не ломается**
- Новый раздел прогресса (`Store.set("x", …)`) есть в `EMPTY` в начале
  `app.js` и в одном из списков `Store.merge`: числовой — побеждает
  большее, текстовый — берётся, только если здесь пусто. Посмотри, что
  выберет перенос прогресса из файла на другое устройство и не потеряет ли
  он сделанное.
- Ключи прогресса (`id` уроков, номера шагов, карточек, вопросов, задач)
  не сдвинуты: `node инструменты/checkorder.js`.
- Всё работает и в режиме без localStorage (`Store.mode() === "memory"` —
  приватное окно): ничего не падает, если в разделе пусто.

**Проверки в инструментах совпадают с движком**
- В `инструменты/checksteps.js` лежат копии `Check.normLines`,
  `Check.python`, `Check.uses`, `Check.cellEq` и `Check.sql`; в
  `.claude/skills/new-practicum/scripts/practicum_check.py` — сверка вывода;
  `инструменты/checkdrills.js` повторяет классификацию `Drills`. Если в
  диффе менялась логика проверки в `app.js`, копия обязана измениться
  так же — иначе CI будет пропускать то, что ученик в браузере не пройдёт,
  или наоборот.

**Маршруты и загрузка**
- Новая страница — в `Pages.find`; её адрес не совпадает ни с одним `id`
  элемента на странице: роутер принимает хэш за якорь, если такой элемент
  есть.
- Содержимое уроков читается только после `Lazy.content(модуль)`;
  все шесть модулей грузятся только там, где они правда нужны.
- Новый файл сайта есть в `SHELL` в `sw.js` (если без него страница не
  откроется) или в `Offline.files`, и в списках `build.py`.

**Доступность и телефон**
- После замены `innerHTML` фокус не теряется: ставится на новый
  содержательный элемент (с `tabindex="-1"`) или на кнопку.
- Состояние передаётся не только цветом: есть текст или `aria-*`.
- Кнопки — `<button type="button">`, всё доступно с клавиатуры.
- Ширина 390 px без горизонтальной прокрутки: длинный код и таблицы
  переносятся или прокручиваются внутри себя.
- Цвета только переменными из `styles.css` (работает тёмная тема); один
  акцент — фиолетовая ручка; новых радиусов, кроме 13 и 7 px, и новых
  анимаций, кроме `ink-in`, нет.

**Тексты интерфейса**
- По-русски, на «вы», без восклицательных знаков; числа со знаменателем
  («12 из 15»), склонение через `plural`.
- Нет иероглифов и других случайных символов U+2E00–U+FEFF.

**Проверки курса**
- `ci.sh` целиком не запускай: он пересобирает «Тетрадь аналитика.html» в
  рабочей папке. Прогони то, что ничего не пишет: `node --check` для
  изменённых JS, `node инструменты/checkorder.js`,
  `node инструменты/checkdrills.js`, `node инструменты/checksteps.js <id>`
  для уроков, чью проверку могла задеть правка.
- `VERSION` в `sw.js` поднимает коммит выпуска (`инструменты/release.sh`);
  до выпуска её отсутствие — не находка, достаточно напомнить.

## Что вернуть

Список находок по серьёзности: блокирует слияние / стоит поправить /
мелочь. Для каждой — файл и строка, что не так, как проверил и как
исправить. Отдельно — что стоит проверить руками в браузере (ты его не
запускаешь). Если всё чисто — так и скажи и перечисли, что прогнал. Файлы
не меняй.
