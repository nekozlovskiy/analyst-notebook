# Тетрадь аналитика

Интерактивный курс подготовки к позиции Junior Data Analyst / Product Analyst.
SQL и Python выполняются прямо в браузере.

**Курс открыт здесь: https://nekozlovskiy.github.io/analyst-notebook/**

---

## Что отдавать ученику

**Ссылку.** Это основной способ: адрес не меняется, поэтому каждая новая
версия курса подхватывает прогресс ученика сама — ничего переносить не нужно.

**Или один файл: `Тетрадь аналитика.html`.** Внутри уже всё — уроки, учебная
база данных, оформление и шрифты, логика проверки. Человек скачивает файл, делает
двойной клик и занимается. Годится, когда ссылку дать нельзя.

Нужен только интернет: редактор кода, Python и SQLite подтягиваются
при первом запуске. Первый запуск Python занимает 15–40 секунд,
дальше мгновенно.

## Без интернета

Сайт кладёт себя в браузер и дальше открывается с диска: страница,
оформление и уже прочитанные уроки работают без связи. Чтобы курс
открывался целиком — все 42 урока, включая вводные 0.1 и 0.2, и учебная база, — есть кнопка
**«Сохранить курс на устройство»** в окне «Прогресс»: около трёх с
половиной мегабайт (вместе со шрифтами), и дальше можно заниматься в метро и в самолёте.

Python остаётся исключением: его движок весит десятки мегабайт, при
первом запуске он всё равно просит связь. SQL без интернета работает.

С телефона курс можно поставить на домашний экран как приложение —
за это отвечает `manifest.webmanifest`.

**Выпуская новую версию, поменяйте `VERSION` в `sw.js`.** Иначе у тех,
кто уже заходил, останется вчерашняя страница из кеша. После смены
версии человек увидит подсказку «курс обновился» и получит новое при
следующей перезагрузке.

## Прогресс

Пройденные уроки, весь написанный код и заметки сохраняются автоматически
в браузере ученика и подхватываются при следующем открытии. Никаких
действий и никаких лишних файлов для этого не нужно.

Проверено на реальных браузерах при открытии файла двойным кликом:

| Браузер | Результат |
|---|---|
| Safari 26 | прогресс сохраняется и возвращается после перезагрузки |
| Chrome 151 | прогресс сохраняется и возвращается после перезагрузки |

Прогресс привязан к браузеру и к адресу, откуда открыт курс. Пока курс
открывают по ссылке, любая новая версия продолжает занятия сама — адрес
тот же. То же верно и для файла: новая сборка, открытая в том же браузере,
подхватывает прогресс прежней.

Перенести занятия в другой браузер или на другой компьютер можно файлом:
в окне «Прогресс» (кнопка со счётчиком уроков в шапке) — «выгрузите
прогресс», а на новом месте просто перетащите этот файл на страницу.
Перенос ничего не стирает: пройденное складывается, а код и заметки,
набранные на новом месте, остаются нетронутыми.

Вернувшегося ученика на главной встречает карточка «продолжить» — урок,
на котором он остановился, или следующий непройденный — и его цифры:
сколько уроков пройдено, сколько времени отдано курсу и сколько дней
подряд он занимается.

Перед оглавлением — схема «Маршрут»: какие модули на каких опираются.
Стрелки берутся из поля `needs` модулей в `lessons.js`, подписи — из
`short`, а места узлов и изгибы стрелок заданы в `Route` в `app.js`
(две раскладки: по горизонтали и для телефона по вертикали). Модуль с
полем `optional` — сейчас это 5, математика, — нарисован пунктиром и
помечен «необязательный» и в оглавлении: к первому офферу хватает
модулей 1–4 и 6. Новый модуль надо добавить в обе раскладки `Route`.

Вопросы из самопроверки возвращаются на главную через 1, 3, 7 и 21 день.
Верный ответ отодвигает вопрос на ступень дальше, ошибка возвращает его
на завтра, верный ответ на последней ступени — вопрос выучен.

Во всех уроках после теории (а в уроке 0.1 — после шагов) стоят карточки «вопрос → ответ»: сначала
ученик вспоминает ответ сам, потом открывает его и отмечает «вспомнил»
или «не вспомнил». Карточки возвращаются в то же повторение на главной,
вперемешку с вопросами самопроверки и по той же лестнице. Сколько раз
человек не вспомнил карточку или ошибся в вопросе, тоже сохраняется.
Эти промахи собраны на странице «Мои ошибки» (`#mistakes`; в шапке —
«Ошибки», на узком экране — в «Меню», а на главной ссылка появляется в
блоке «Повторение», как только есть хоть одна ошибка): уроки идут по
числу ошибок, в каждом — вопросы и карточки с правильным ответом под
спойлером, их состоянием в повторении и ссылкой перечитать теорию.

Единственный случай, когда браузер не даст сохранять, — **приватное окно**
или очень строгие настройки приватности. Курс это определяет сам,
показывает предупреждение вверху и предлагает выгрузить прогресс в файл,
чтобы результат не пропал. В обычном окне такого не бывает.

## Для себя: как править курс

Собранный html руками не правится — он пересобирается из исходников.

| Файл | Что внутри |
|---|---|
| `index.html` | каркас страницы |
| `styles.css` | оформление, светлая и тёмная темы; в начале — `@font-face` для шрифтов из `fonts/` |
| `fonts/` | шрифты Onest, Literata, JetBrains Mono, Bad Script (woff2, по наборам символов) — свои, без Google Fonts |
| `lessons.js` | карта курса: модули, уроки, флаг `ready`, реплики наставника |
| `content-core.js` | общие куски уроков: описание базы, прологи для Python |
| `glossary.js` | словарь терминов: объяснения простыми словами и поиск терминов в тексте урока |
| `content-m0.js` … `content-m6.js` | содержание уроков по модулям: теория, задача, эталон, подсказки, решение, карточки; в `content-m0.js` — шаги урока 0.1 |
| `data.js` | учебная база «Дельта Маркет»: SQL-дамп и CSV |
| `app.js` | логика: редактор, запуск кода, проверка, прогресс, повторение, поиск и клавиши |
| `sw.js` | работа без интернета: что кладётся в кеш браузера и когда обновляется |
| `manifest.webmanifest` | описание приложения для установки на домашний экран |
| `favicon.svg`, `apple-touch-icon.png`, `og.png` | иконки и картинка-превью ссылки |
| `инструменты/og.html`, `инструменты/icon.html` | исходники картинок: открыть на локальном сервере и снять экран |
| `инструменты/devserver.py` | локальный сервер без кэша для проверки правок |
| `build.py` | сборщик единого файла |

Порядок работы:

1. Правите исходники.
2. Проверяете на локальном сервере без кэша — правка видна сразу после
   перезагрузки страницы: `python3 инструменты/devserver.py 8779`,
   затем открыть http://localhost:8779. На localhost `sw.js` работает
   «сначала сеть», поэтому кеш правок не прячет.
3. Пересобираете файл для отправки:

```bash
python3 build.py
```

На сайте модули уроков и учебная база грузятся по требованию: главная
не тянет ни то ни другое, урок подгружает только свой модуль, база
приходит перед первым запуском кода. В собранный файл `build.py` кладёт
всё внутрь заранее — у файла, открытого с диска, рядом ничего нет.

### Как открыть новый урок

У каждого урока в `lessons.js` есть флаг `ready`. Урок становится доступным,
когда `ready: true` **и** в `content-mN.js` своего модуля появился объект
с его `id`.
После правки — `python3 build.py`.

### Как добавить карточки

Карточки — поле `cards` в объекте урока, рядом с `quiz`:

    cards: [
      { q: "Чем LEFT JOIN отличается от INNER JOIN?",
        a: "INNER оставляет только строки с парой с обеих сторон…" }
    ]

От 6 до 12 на урок, одна мысль на карточку, порядок — как в теории.
Новые карточки дописывайте в конец массива: номер карточки — её ключ
в расписании повторения. Правила написания — в `ПРОГРЕСС.md`, раздел
«Карточки». Перед сборкой:

    node инструменты/checkcards.js --require m0 m1 m2 m3 m4 m5 m6

Скрипт проверяет формат, длину, разрешённые теги (`<code>`, `<pre>`),
посторонние символы и то, что каждое число из ответа есть в теории урока
или в `ПРОГРЕСС.md`.

### Как добавить термин в словарь

Термины из `glossary.js` подчёркиваются в уроках сами — первое
упоминание в каждом разделе, — а по тапу под абзацем раскрывается
объяснение. Все термины собраны на странице «Словарь» (`#glossary`,
ссылка в шапке, на узком экране — в «Меню»; термины находятся поиском); `#glossary/<id>` открывает
её на нужном термине. Страница делит термины по `kind` — новый `kind`
нужно добавить в список групп в `renderGlossary`, иначе термин на ней
не появится. Запись термина:

    { id: "left-join", t: "LEFT JOIN", kind: "sql",
      forms: ["LEFT JOIN", "LEFT"],
      plain: "соединение, которое сохраняет все строки первой таблицы…",
      when: "в ответе должны остаться все, даже без пары…",
      lesson: "m1l1" }

`forms` — по чему узнавать термин: латиница ищется целым словом
с учётом регистра, кириллица — по началу слова («средн чек» найдёт
«среднего чека»), обратная кавычка в начале — только внутри `<code>`.
`plain` — до 40 слов и только слова, которые ученик уже знает;
`when` — по каким словам в задаче узнать, что пора применить.
Правила — в шапке `glossary.js`. Перед сборкой:

    node инструменты/checkterms.js

Скрипт проверяет записи и печатает, сколько терминов нашлось в каждом
уроке. `--show <id>` показывает каждое совпадение с окружением — так
ловятся ложные, `--missing m2` — кандидаты в словарь из модуля 2.

### Как добавить шаги в пошаговый урок

Уроки 0.1 (SQL) и 0.2 (Python) — пошаговые: в карте курса у них
`steps: true`, а в объекте урока вместо теории и одной задачи — массив
шагов:

    steps: [
      { title: "Отфильтровать строки: WHERE",
        body: "<p>…</p>",
        starter: "SELECT user_id, signup_date\nFROM users;",
        expected: { ordered: false, columns: [...], rows: [...] },
        hint: "…",
        solution: "SELECT …" }
    ]

`expected` устроен как у основной задачи SQL-урока. Новые шаги
дописывайте в конец массива: номер шага — ключ в прогрессе ученика.
Начальный запрос лучше делать запускаемым: новичок сразу видит
таблицу, а «Проверить» объясняет, чего не хватает. Перед сборкой:

    node инструменты/checksteps.js m0l1

Скрипт прогоняет решение каждого шага на учебной базе и сверяет
с `expected` по тем же правилам, что проверка в браузере.
`--try 3 "SELECT …"` показывает, что увидит ученик на шаге 3.
Итоговая фраза урока — поле `finish`.

**Шаги на Python.** Урок с `kind: "python"` запускает код шага в
браузерном Python (Pyodide) после пролога модуля 2 — в объекте урока
`packages: ["pandas"]`, `data: window.SH.pyData`,
`prelude: window.SH.pyPrelude`, — и сверяет напечатанное:
`expected: { stdout: "…" }`, построчно, без учёта пробелов по краям.
Каждый запуск идёт с чистого листа: переменные соседних шагов не
видны. `checksteps.js` прогоняет такие шаги локальным `python3`, но
локальный pandas обычно новее браузерного (2.2), поэтому окончательно
урок проверяют в браузере. В эталонах не печатайте `dtypes` и столбцы
с текстом — их вид зависит от версии pandas.

**Эталон основной задачи показывается с закрытыми числами.** В блоке
«ожидаемый результат» видны столбцы, строки и текст (каналы, города,
даты), а числа заменены на «•••» — так видно, какой формы нужен ответ,
но нельзя подогнать запрос под готовые цифры. Числа открываются кнопкой
«показать числа» и сами — после верного решения или в уже пройденном
уроке. Даты вида `2024-01` числами не считаются и не прячутся.

**Порядок прохождения.** Поле `before: "m2l1"` в карте курса ставит
урок прямо перед указанным: 0.2 стоит в модуле 0, но кнопка «дальше»,
карточка «продолжить» и итог модуля ведут к нему после 1.8, а от него —
в 2.1. Номера и оглавление остаются по местам в модулях.

**Номер урока — это его место в модуле, а не `id`.** Номер считается
по порядку в `lessons.js`, прогресс ученика хранится по `id`. Поэтому
уроки можно переставлять, не трогая `id`: так 2026-09-24 GROUP BY
(`m1l3`) стал 1.1, проект (`m1l8`) — 1.7, ClickHouse (`m1l7`) — 1.8,
а ЦПТ (`m3l2`) встала перед доверительным интервалом (`m3l1`). После
перестановки ищите в текстах «урок N.N», «прошлый урок» и «следующий
урок» — номера в текстах написаны руками.

### Как добавить практикум в обычный урок

Практикум — те же шаги, но внутри обычного урока: раздел «Практикум»
встаёт между карточками и основной задачей (сейчас он есть в 1.1, 1.3 и 1.4).
В объекте урока — поле `practicum`:

    practicum: {
      intro: "…",                  // абзац под заголовком раздела
      schema: window.SH.sqlSchema,
      done: "…",                   // что сказать, когда все шаги решены
      steps: [
        { title, body, starter, expected, hint, solution,
          ba: { before: { columns, rows }, after: { columns, rows },
                hl: ["total"], keep: [0, 3], note: "…" },
          task: "<p><strong>Задание.</strong> …</p>" }
      ]
    }

`ba` — таблицы «было → стало» на настоящих строках базы: `hl` —
новые столбцы «стало», `keep` — строки «было», которые останутся
(с нуля); их выделяет ручка. Под таблицами — `note`, дальше `task`.
Урок практикум не отмечает — пройденным его делает основная задача.
Прогресс шагов хранится с меткой `p` («m1l2:p0», код — «m1l2:ps0»),
поэтому новые шаги тоже дописывайте только в конец. Проверка:

    node инструменты/checksteps.js m1l2

## Учебные данные

База «Дельта Маркет» — интернет-магазин, данные за январь–сентябрь 2024,
сгенерированы детерминированно (seed = 42).

```
users    220 строк   user_id, signup_date, channel, city, platform
orders   215 строк   order_id, user_id, order_date, revenue, status
events  1488 строк   event_id, user_id, event_date, event_name
```

Одни и те же данные используются в SQL- и Python-уроках, поэтому ответы
сверяются между модулями: если числа разошлись — где-то ошибка.

SQL-движок — SQLite (sql.js). Оконные функции и CTE поддерживаются,
функции для дат отличаются от PostgreSQL и ClickHouse — это разбирается
в самих уроках.
