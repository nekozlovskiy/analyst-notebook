# Первый визит: модуль 0 «Старт» и пошаговый урок 0.1

Дата: 2026-09-19. Ветка: `first-visit` (от `cards-modules-2-6`).

## Зачем

Ученик приходит по ссылке от наставника и начинает с нуля. Сейчас его
встречают две проблемы.

- На главной нет действия «начать». Под заголовком карта из 40 клеток
  без подписей, а единственная кнопка с текстом — «Перенесите прогресс»,
  которая новичку не нужна. `Stats.resume()` намеренно не даёт новичку
  карточку «продолжить».
- Урок 1.1 начинается сразу с JOIN. `SELECT`, `WHERE`, `ORDER BY`,
  `GROUP BY`, `COUNT` и `SUM` он считает известными, хотя объясняются
  они только в 1.3. Первый запуск кода случается после получаса чтения.

Это первый из четырёх подпроектов улучшения клиентского опыта. Порядок
остальных: скорость и надёжность, занятия с телефона, «возвращаться
каждый день». У каждого свой дизайн и план.

## Объём

- Модуль 0 «Старт» с одним уроком 0.1 «Первый запрос».
- Новый вид урока — пошаговый: теория нарезана на шаги, у каждого свой
  редактор и своя проверка.
- Главная для новичка: карточка «С чего начать» → 0.1.
- Не входит: вводный урок по Python перед 2.1 (тот же вид урока,
  отдельный цикл), фоновая загрузка Python, правки мобильной вёрстки
  сверх того, что нужно самому уроку 0.1.

## Карта курса

В `lessons.js` первым идёт модуль:

```js
{ id: "m0", num: 0, title: "Старт", sub: "…", say: "…", sayDone: "…",
  weeks: "≈ 45 минут",
  lessons: [
    { id: "m0l1", title: "Первый запрос", kind: "sql", ready: true, steps: true,
      desc: "SELECT, WHERE, ORDER BY, GROUP BY — с нуля до группировки",
      say: "…", sayTask: "…" }
  ] }
```

- Номер урока складывается из номера модуля и позиции (`m.num + "." +
  (i + 1)`), поэтому урок получает номер 0.1, а 1.1–6.6 не сдвигаются.
  Вставлять урок в начало модуля 1 нельзя: в текстах уроков есть ссылки
  вида «урок 1.3».
- Флаг `steps: true` в карте курса нужен, чтобы оглавление и главная
  знали вид урока, не загружая `content-m0.js`.
- Карта на обложке, оглавление, поиск, счётчик «из 41», «Сохранить курс
  на устройство» и загрузка по требованию перебирают модули из карты
  и подхватят `m0` без правок.
- Итога модуля у `m0` нет: после урока 0.1 ссылка «Модуль закрыт —
  посмотреть итог» не показывается, вместо неё ведём к 1.1.

## Главная

- Новичку — человеку без единого пройденного урока и без открытых
  уроков (`Stats.started()` ложно) — под заголовком показывается
  карточка того же вида, что «Вы остановились здесь» (`.resume`),
  с подписью «С чего начать»: «0.1 Первый запрос», описание урока,
  кнопка «Начать».
- Реплика на поле «начните с первого модуля, остальное подождёт»
  меняется на «начните с урока 0.1, даже если SQL уже видели мельком».
- Строка «Занимались в прошлой версии курса? Перенесите прогресс…»
  уходит с обложки под оглавление. Перетаскивание файла прогресса
  работает на всей странице, как и раньше; выгрузка остаётся в окне
  «Прогресс».
- Те, кто уже занимается, ничего нового на главной не видят.
  `Stats.resume()` после последнего урока идёт по кругу к началу курса
  и нашёл бы непройденный 0.1. Правило: урок `m0l1` исключается
  из поиска «следующего непройденного», если у человека пройден хотя бы
  один урок модулей 1–6. Из оглавления 0.1 открыть может кто угодно.

## Данные урока

`content-m0.js`, по образцу остальных файлов:

```js
window.CONTENT.m0l1 = {
  intro: "…",
  duration: "≈ 45 минут",
  plan: [ { m: "35 мин", w: "Восемь шагов: от первого запроса до GROUP BY" },
          { m: "5 мин",  w: "Карточки" },
          { m: "5 мин",  w: "Как устроены следующие уроки" } ],
  schema: window.SH.sqlSchema,
  steps: [
    { title: "Первый запрос",
      body: "<p>…</p>",
      starter: "SELECT * FROM users LIMIT 5;",
      expected: { columns: [...], rows: [...], ordered: true },
      hint: "…",
      solution: "…" }
  ],
  after: "<p>Как устроены следующие уроки…</p>",
  cards: [ { q: "…", a: "…" } ],
  links: [ … ]
};
```

- `body` — 3–6 предложений, одна мысль. Разметка как в теории.
- `expected` устроен так же, как у основной задачи SQL-урока, и
  проверяется той же функцией `Check.sql` с тем же допуском 0,011.
- `hint` — одна подсказка; `solution` — готовый запрос.
- `after` — блок «Как устроены следующие уроки»: из каких частей
  состоит обычный урок, сколько он занимает, что прогресс сохраняется
  сам, что на главной ждёт повторение.
- Карточки 6–8, по правилам из `ПРОГРЕСС.md`; попадают в повторение.
- Самопроверки (`quiz`), тренажёра (`drills`), основной задачи
  (`ticket`, `starter`, `expected` верхнего уровня) и теории у урока 0.1
  нет: их роль выполняют шаги.

Поле `steps` описывается в шапке `content-core.js` рядом с `cards`.

### Шаги

Все решения прогнаны на учебной базе (SQLite из `data.js`).

| № | Шаг | Что делает ученик | Проверка |
|---|-----|-------------------|----------|
| 1 | Первый запрос | запрос уже написан: `SELECT * FROM users LIMIT 5` — запустить и проверить | 5 строк, user_id 1–5 |
| 2 | Нужные столбцы | `user_id`, `channel`, `platform` первых десяти пользователей | 10 строк |
| 3 | WHERE | `user_id`, `signup_date` пользователей из Казани, текст в одинарных кавычках | 47 строк |
| 4 | AND, OR, IN, сравнения | оплаченные заказы дороже 5000: `order_id`, `user_id`, `revenue` | 28 строк |
| 5 | ORDER BY и LIMIT | пять самых дорогих оплаченных заказов | первая сумма 10 177,29, пятая 8 173,74, шестая 7 779,49 — ничьей на границе нет |
| 6 | COUNT, SUM, AVG, ROUND, AS | одной строкой: `orders_cnt`, `revenue`, `avg_check` | 189, 653 428,78, 3 457,30 |
| 7 | GROUP BY | `channel`, `users_cnt`, от большего к меньшему | organic 75 … partner 6, все числа разные |
| 8 | Всё вместе | топ-5 покупателей по выручке оплаченных заказов: `user_id`, `orders_cnt`, `revenue` | пятое место 15 301,00, шестое 15 252,32 |

После шага 8 ученик знает всё, что нужно для задачи урока 1.1, кроме
самого JOIN и `COALESCE`, которые объясняет 1.1.

## Страница пошагового урока

Шапка и план занятия — как у всех уроков. Якорная навигация:
«Шаги», «Карточки», «Как дальше», «Что почитать». Дальше блок «Шаги»
лентой на одной странице (вариант 1 из макета):

- Над первым шагом — тот же раскрывающийся блок `details.schema`,
  что в задаче обычного урока, с подписью «Какие таблицы есть в базе»
  и содержимым `C.schema`.
- Шаги пронумерованы. Будущие видны серыми заголовками, чтобы ученик
  видел, сколько осталось.
- Открыт один шаг — первый непройденный: заголовок, текст, редактор,
  кнопки «Запустить» и «Проверить», под ними таблица результата.
  «Проверить» всегда сначала выполняет то, что сейчас в редакторе.
- Начальный запрос шага запускается без ошибки (например, у шага 3 —
  `SELECT user_id, signup_date FROM users;`): новичок сразу видит
  таблицу, а «Проверить» объясняет, чего не хватает.
- «Не получается» показывает подсказку; после неё появляется «Показать
  решение», которое подставляет решение в редактор. Шаг засчитывается
  только после «Проверить».
- Верный ответ: шаг сворачивается в строку с галочкой, названием и
  первой строкой запроса ученика моноширинным; следующий шаг
  раскрывается и прокручивается в зону видимости. Свёрнутый шаг можно
  раскрыть щелчком и перечитать; редактор в нём не создаётся, запрос
  показан текстом.
- Редактор CodeMirror создаётся только у открытого шага и убирается,
  когда шаг сворачивается: на телефоне не бывает восьми редакторов сразу.
- Ctrl/Cmd+Enter в редакторе — «Запустить», как в обычном уроке.
- После последнего шага: «Урок пройден», кнопка «Перейти к следующему
  уроку» (1.1), ниже — карточки, блок `after` и ссылки.
- Внизу урока — та же навигация, что у всех уроков: соседние уроки,
  «Карта курса» и кнопка отметки «пройден».
- При открытии урока движок SQL и учебная база загружаются заранее,
  в свободное время браузера (`idle`), чтобы первое «Запустить»
  сработало без ожидания.

Оформление следует правилам из `ПРОГРЕСС.md`: рамку получают только
редактор и таблица вывода, шаги отчёркиваются линейками, акцент —
фиолетовая ручка у номера открытого шага, зелёная галочка — состояние
«пройден», радиусы 13 и 7 px.

## Прогресс

- Новая корзина `steps` в `Store`: ключ `m0l1:3` (урок и номер шага
  с нуля), значение — время прохождения. Добавляется в `EMPTY` и
  в `Store.merge` в группу числовых корзин (побеждает большее).
- Код шага — в корзине `code` под ключом `m0l1:s3`. Правило слияния
  у `code` уже есть: из файла кладётся только туда, где пусто.
- Урок засчитывается (`done.m0l1`), когда пройдены все шаги. Общая
  кнопка внизу урока «Пройден — снять отметку» у пошагового урока
  снимает и отметки шагов: ученик снова начинает с шага 1, написанный
  код остаётся.
- Номер шага — позиция в массиве, поэтому новые шаги дописываются
  в конец, как карточки.
- Время на уроке считает тот же таймер, что у остальных уроков.

## Код

Новый объект `Steps` в `app.js`, рядом с `Flash` и `Review`:

- `Steps.render(L, C, box, onFinish)` — единственная точка входа: рисует
  ленту шагов урока `L` с содержимым `C` в контейнер `box`; `onFinish(fresh)`
  вызывается, когда пройдены все шаги.
- Запуск берёт `Engine.sql()`, вывод — существующую отрисовку таблицы
  результата, проверку — `Check.sql`, сохранение — `Store`.
- Страница урока (`renderLesson`) при `C.steps` рисует шапку, план,
  навигацию, вызывает `Steps.render` и дальше карточки, `after`, ссылки.
  Разделы теории, задачи, тренажёра, самопроверки и заметок для такого
  урока не рисуются.

Если общие куски обычного урока (запуск, вывод таблицы, настройка
CodeMirror) сейчас спрятаны внутри `renderLesson`, их выносят в функции
верхнего уровня и обычный урок переводят на них же — без изменения
его поведения.

## Сборка и инструменты

- `build.py`: `content-m0.js` добавляется в `LAZY` первым.
- `инструменты/checkcards.js`: модули 0–6 вместо 1–6.
- Новый `инструменты/checksteps.js`: прогоняет `solution` каждого шага
  на учебной базе и сверяет с `expected` по правилам `Check.sql`.
  Печатает по строке на шаг, код выхода 1 при расхождении.
- `sw.js`: поднять `VERSION`.
- `README.md` и `ПРОГРЕСС.md`: модуль 0, вид урока `steps`, как
  добавить шаги.

- `node инструменты/checksteps.js m0l1` — все 8 шагов совпадают.
- `node инструменты/checkcards.js --require m0 m1 m2 m3 m4 m5 m6`.

  на главной «С чего начать» → 0.1; все 8 шагов проходят «Проверить»;
  после перезагрузки открыт первый непройденный шаг; после 8-го урок

- В браузере, профиль с прогрессом (`localhost:8779`): главная и
  «продолжить» как раньше, 0.1 не предлагается.
- Ширина 375 px: шаг, редактор и таблица без горизонтальной прокрутки
  страницы.
- Обычный SQL-урок (1.1) и Python-урок (2.1) работают как раньше:
  запуск, проверка, подсказки, решение.
- `python3 build.py`: сборка в один файл открывает 0.1 и проходит шаг 1.
- Ошибок в консоли нет.
