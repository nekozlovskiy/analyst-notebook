# Модуль 7 «Финальный проект»: тестовое задание «Вилки»

Дата: 2026-10-13. Этап 4 плана улучшений (раздел 6, «Сквозной финальный проект»).

## Зачем

Проекты курса (1.8, 3.7, 4.8) — каждый одного типа и на знакомых данных. Тестовое задание в компанию устроено иначе: незнакомая база, несколько дней, SQL, pandas, A/B, дашборд и записка в одной работе, и результат сдаётся файлами и ссылками. Финальный проект репетирует именно это и оставляет ученику три вещи для портфолио: ноутбук Colab, дашборд DataLens и записку.

Критерий успеха: ученик за 3–5 вечеров проходит семь этапов на базе «Вилки», каждое ключевое число этапа совпадает с расчётом курса, записка проходит проверку смысловыми блоками, а ноутбук, дашборд и записка лежат по публичным ссылкам.

## Решения владельца курса

- Формат — гибрид: работа идёт снаружи (Google Colab, DataLens, документ), курс проверяет ключевые числа каждого этапа полями и записку смысловыми блоками, затем открывает эталон.
- Данные — новая незнакомая база, предметная область — доставка еды («Вилка»).
- Место — новый модуль 7 из уроков-этапов уже существующих видов; срок 3–5 дней — рекомендация в тексте, без таймера.
- Рабочее место — Google Colab: SQL через `sqlite3` в Python, pandas, scipy там уже стоят.
- Выпуск — два PR: (1) генератор, файл, модуль и уроки 7.1–7.4, уроки 7.5–7.7 в карте с `ready: false`; (2) уроки 7.5–7.7.

## База «Вилки»

Генератор `инструменты/gen_vilka.py` по образцу `gen_taxi.py`: только `random.Random` с фиксированным зерном, `--check` сверяет результат с файлами в ветке и печатает контрольные числа. Период — 1 января – 30 июня 2025 года.

| Таблица | Строк (ориентир) | Столбцы |
| --- | --- | --- |
| `customers` | ≈ 6000 | `customer_id`, `signup_date`, `city` (4 города), `platform` (android / ios / web / internal), `channel` |
| `restaurants` | ≈ 150 | `restaurant_id`, `city`, `cuisine` |
| `orders` | ≈ 40 000 | `order_id`, `customer_id`, `restaurant_id`, `created_at`, `items_sum`, `delivery_fee`, `status` (delivered / cancelled) |
| `experiment` | ≈ 8000 | `customer_id`, `group` (control / test), `assigned_at` |

Точные размеры фиксирует генератор; в тексты уроков идут только числа, напечатанные им и сверенные запросом.

**Эксперимент.** 4 недели в мае 2025 года. Test — бесплатная доставка для заказов от 1500 ₽, control — платная. Заложенный эффект: конверсия в заказ у test выше, средний чек смещается к порогу, «Вилка» теряет плату за доставку. Решение зависит от того, окупает ли прирост заказов потерянную плату, а не от p-value. SRM в данные не закладывается: сплит честный, проверка SRM — одно из полей с ответом «сплит в порядке» (p-value хи-квадрата выше 0,05).

**Ловушки, каждая ловится полем:**
1. Дубли выгрузки: около 1% заказов повторены целой строкой с тем же `order_id`.
2. Тестовые аккаунты: несколько десятков `customer_id` с `platform = 'internal'` и сотнями заказов; часть попала в эксперимент.
3. Отменённые заказы (`status = 'cancelled'`) в выручку не идут.
4. Средний чек на заказ и выручка на пользователя дают разные выводы по эксперименту.
5. GMV (`items_sum`) — деньги ресторанов; выручка «Вилки» в проекте — `delivery_fee` плюс комиссия ресторанов. Комиссия — 20% от `items_sum` доставленных заказов; ставка задана в техзадании и одинакова во всех этапах.

**Файлы.**
- `vilka.xlsx` — четыре листа, собирает `инструменты/mkxlsx.py` (третья книга в `BOOKS`); данные берёт из файла генератора. Размер ≈ 1 МБ, офлайн-сборка вырастет примерно на 1,3 МБ.
- Источник для `mkxlsx.py` и проверок — CSV-строки в новом `data-vilka.js` (`window.VILKA`), который генератор пишет так же, как `data-taxi.js`. Сайт этот файл не грузит: ученик работает с xlsx.
- `инструменты/shop.db` получает таблицы «Вилки» (через `mkdb.py`), чтобы `checknums.js` сверял поля запросами.

## Модуль 7

`lessons.js`: модуль `{ id: "m7", num: 7, short: "Финальный проект", needs: ["m3", "m4"], … }`, уроки `m7l1` … `m7l7`, все с `file: "vilka.xlsx"`, кроме `m7l1` и `m7l7`, где ссылка на файл — в тексте.

| Урок | Вид | Ученик делает | Курс проверяет |
| --- | --- | --- | --- |
| 7.1 Техзадание и рабочее место | `text` | Письмо Арины, руководителя продукта «Вилки». Открыть Colab, загрузить `vilka.xlsx`, разложить листы в SQLite готовым кодом из 5–6 строк, написать ответ: вопросы к заказчику и план этапов | смысловые блоки (вопросы к заказчику, план, сроки, допущения) |
| 7.2 Качество данных | `sheet` | Дубли, тестовые аккаунты, отмены | 4 числа: дублей, тестовых аккаунтов, их заказов, чистых заказов |
| 7.3 SQL-выгрузка | `sheet` | GMV и выручка «Вилки» по месяцам, доля отмен, лучший город | 4–5 чисел |
| 7.4 pandas: когорты и чек | `sheet` | Удержание на первый месяц по когортам регистрации, средний чек | 4–5 чисел |
| 7.5 A/B: бесплатная доставка | `sheet` | SRM, конверсия, p-value, средний чек, выручка на пользователя с учётом потерянной платы | 5–6 чисел, включая p-value SRM |
| 7.6 Дашборд | `sheet` | Дашборд DataLens по чистым данным по правилам урока 4.7 | 4–5 чисел, часть — с селектором |
| 7.7 Записка | `text` | Записка Арине: решение по эксперименту и деньги | смысловые блоки, как в 4.8; чек-лист портфолио |

Все этапы считаются на чистых данных из 7.2: без дублей, без `internal`, выручка — без отмен. Каждый следующий урок напоминает это одной строкой в `schema`.

Каждый урок: короткая теория только о новом (Colab и SQLite в 7.1, GMV против выручки в 7.3, экономика эксперимента в 7.5), тикет, `schema`, поля или критерии, три подсказки, эталон — полный код этапа для Colab, тренажёр на 2–3 задачи (`nums` или `text`), квиз 4–6 вопросов, карточки 4–6. Тон и правила — как во всём курсе: числа со знаменателем, без восклицаний.

7.1: рекомендация «3–5 вечеров, как на настоящем тестовом». 7.7: чек-лист портфолио — ноутбук Colab с публичной ссылкой, дашборд по публичной ссылке на учебных данных, записка; README по уроку 6.2.
