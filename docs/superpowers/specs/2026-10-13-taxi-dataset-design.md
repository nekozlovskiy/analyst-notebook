# Второй датасет «Дельта Такси» и урок 6.4 «Чужая схема: такси»

Дата: 2026-10-13. Этап 4 плана улучшений (раздел 6: «Второй датасет для собеседования»). Часть 1 из 2; часть 2 — режим «лайв-собеседование» — отдельный спек после слияния этой.

## Зачем

Все SQL-задачи курса идут на базе «Дельта Маркета», и к модулю 6 ученик знает её схему наизусть. На собеседовании дают незнакомую базу, и первые 10 минут уходят на то, чтобы понять, что в ней лежит: зерно таблицы, ключи, пропуски, перечень статусов, формат времени. Этому курс сейчас не учит.

Критерий успеха: ученик за несколько запросов описывает незнакомую схему (сколько строк, что одна строка значит, где NULL и почему, какие значения у статусов), задаёт уточняющие вопросы до решения и решает типовые задачи такси — доля отмен, время подачи, загрузка водителя, удержание пассажиров — на базе, которую видит впервые.

## Решения владельца курса

- Предметная область — такси.
- Место — новый SQL-урок в модуле 6 сразу после 6.3 «SQL на собеседовании».

## Данные

Город-агрегатор «Дельта Такси», заказы с 1 января по 30 июня 2024, три города: Москва, Казань, Екатеринбург.

```sql
CREATE TABLE riders (
  rider_id    INTEGER PRIMARY KEY,
  signup_date TEXT NOT NULL,          -- 'YYYY-MM-DD'
  city        TEXT NOT NULL,
  platform    TEXT NOT NULL           -- ios / android
);
CREATE TABLE drivers (
  driver_id   INTEGER PRIMARY KEY,
  city        TEXT NOT NULL,
  joined      TEXT NOT NULL,          -- 'YYYY-MM-DD'
  car_class   TEXT NOT NULL           -- econom / comfort / business
);
CREATE TABLE trips (
  trip_id      INTEGER PRIMARY KEY,
  rider_id     INTEGER NOT NULL,
  driver_id    INTEGER,               -- NULL, если машина не нашлась
  city         TEXT NOT NULL,
  tariff       TEXT NOT NULL,         -- econom / comfort / business
  requested_at TEXT NOT NULL,         -- 'YYYY-MM-DD HH:MM'
  pickup_at    TEXT,                  -- NULL без подачи
  dropoff_at   TEXT,                  -- NULL, если поездки не было
  status       TEXT NOT NULL,         -- completed / cancelled_rider / cancelled_driver / no_driver
  distance_km  REAL,                  -- NULL, если поездки не было
  price        REAL,                  -- NULL, если поездки не было
  surge        REAL NOT NULL,         -- коэффициент наценки, 1.0 — без неё
  rider_rating INTEGER                -- 1–5, NULL, если не оценил
);
```

- Порядок величины: около 2 000 пассажиров, 300 водителей, 8 000 заказов. Итоговый CSV — не больше 400 КБ.
- Черты «чужой схемы», ради которых она и нужна: время строкой с часами и минутами; `driver_id`, `pickup_at`, `dropoff_at`, `price` пусты по разным причинам в зависимости от статуса; четыре статуса; оценку ставят не все; у одного пассажира много заказов, у водителя — много поездок (зерно `trips` — заказ, а не поездка).
- Сюжет, который находят задачи урока: вечерний пик 18:00–21:00 — наценка выше и больше `no_driver`; в Екатеринбурге с апреля водителей не хватает — растёт доля `no_driver` и время подачи; comfort дороже econom, business — редкий и самый дорогой.
- Генератор `инструменты/gen_taxi.py` — детерминированный (фиксированное зерно, только `random.Random`), печатает контрольные числа (строк по таблицам, доли статусов по городам и месяцам, средняя подача по часам) и пишет `data-taxi.js`: `window.DATA.taxiSQL` (DDL) и `taxiRidersCSV`, `taxiDriversCSV`, `taxiTripsCSV`. Результат зафиксирован текстом в репозитории, как журнал приложения; генератор нужен, чтобы пересобрать.

## Как грузится

- `data-taxi.js` — отдельный файл, грузится по требованию (`Lazy.taxi()`), в `data.js` такси нет: остальные SQL-уроки не качают лишнего.
- `Engine.sql(code)` принимает необязательный текст запроса: если в нём есть имя таблицы такси (`trips`, `drivers`, `riders` целым словом), перед выполнением грузится `data-taxi.js` и таблицы один раз дописываются в ту же базу в браузере (`fillFromCsv`). Все вызовы — `Run.sql`, шаги практикума, основная задача — передают свой код. Так работает и песочница: запрос к `trips` подтянет такси сам.
- У урока в `lessons.js` — `base: "taxi"`: пока ученик читает теорию, такси подгружается в фоне (как сейчас `Lazy.data()`).
- Офлайн: `data-taxi.js` в `Offline.files` и в `LAZY` у `build.py`; в `ci.sh` — синтаксис и `version_bumped`.
- Проверки: `инструменты/mkdb.py` дописывает такси в `shop.db` — `checkdrills.js`, `checksteps.js`, `checksql.js` работают без изменений.
- Подсказки по схеме у редактора (`CodeKit`) берут столбцы из `C.schema` урока — для 6.4 там описание трёх таблиц такси.

## Содержание урока

### Теория

1. Первые 10 минут с чужой базой: список таблиц и столбцов; сколько строк; что значит одна строка (зерно); ключи и связи; где NULL и почему; перечень значений у статусов и категорий (`SELECT status, COUNT(*) … GROUP BY`); формат времени; диапазон дат.
2. Вопросы интервьюеру до первого запроса: что считать заказом и поездкой, входят ли отмены, в каком часовом поясе время, что делать с `no_driver`.
3. Метрики такси: доля заказов, закончившихся поездкой; доля отмен по сторонам; время подачи (`pickup_at − requested_at`, минуты через `julianday`); загрузка водителя; доля поездок с наценкой; средний чек поездки.
4. Время с часами в SQLite: `strftime('%H', requested_at)`, `(julianday(b) − julianday(a)) * 24 * 60`.
5. Ловушки: среднее по таблице с NULL; доля отмен от поездок вместо заказов; `COUNT(driver_id)` против `COUNT(*)`; JOIN водителей без LEFT теряет `no_driver`.

### Практикум (6–7 шагов)

Знакомство со схемой по шагам: строки по таблицам → статусы и их доли → где пусто `driver_id` и при каком статусе → диапазон дат и формат времени → минуты подачи у одной поездки → заказы по часам суток → доля поездок по городам.

### Задача

Тикет от продакта: «Где и когда теряем заказы?» — доля заказов, закончившихся поездкой, по городу и часу суток (или блоку часов), с сортировкой, где хуже всего. Эталон и числа — при написании.

### Тренажёр (10–12 задач `sql`)

Топ-3 водителя по выручке в каждом городе (окно); первая поездка каждого пассажира; пассажиры без единой поездки; средняя подача по тарифу; доля поездок с наценкой по часам; перерыв водителя дольше 7 дней (`LAG`); недельное удержание пассажиров первой недели; водители, работавшие во всех трёх месяцах квартала; средняя оценка с учётом NULL; выручка по месяцам и городам с долей города; доля `cancelled_driver` у водителей с оценкой ниже 4.

### Quiz, карточки, ссылки

6 вопросов (зерно таблицы, NULL в среднем, доля от чего, LEFT JOIN и `no_driver`, минуты через `julianday`, вопросы интервьюеру), 6 карточек, 2–3 ссылки (статьи о чтении незнакомой схемы и о метриках двусторонних рынков).
