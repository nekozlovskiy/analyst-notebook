# Пробное собеседование `#mock`

Дата: 2026-10-13. Этап 4 плана улучшений, часть 2 из 2 спека
`2026-10-13-taxi-dataset-design.md` (часть 1 — датасет «Дельта Такси» и урок 6.4, PR #81).

## Зачем

Курс тренирует по урокам: задача всегда рядом с теорией, есть подсказки и
разбор. На собеседовании всё наоборот — незнакомая задача, время идёт, разбора
нет. Пробное собеседование даёт эту обстановку: 45 минут, набор заданий,
которых ученик не видел, отчёт в конце. Его можно проходить сколько угодно раз
и видеть, растёт ли результат.

Критерий успеха: ученик проходит попытку целиком на телефоне и на ноутбуке,
получает отчёт «SQL k из 3 · вопросы k из 5 · кейс k из N · M мин» со ссылками
на уроки для повторения, а история попыток сохраняется в прогрессе и
переживает экспорт и импорт.

## Решения владельца курса

1. Экзамен на время, а не диалог с интервьюером.
2. SQL-задачи — новый пул только для собеседования.
3. Продуктовый кейс — свободный ответ, после сдачи эталон и самопроверка по чек-листу.
4. Отдельная страница, открыта всегда; до урока 6.4 — строка «лучше после урока 6.4», не замок.
5. Верно ли решена SQL-задача — только в отчёте. «Запустить» показывает таблицу без вердикта.

## Страница

Адрес `#mock`, заголовок «Пробное собеседование». `#interview` уже занят
страницей «К собеседованию» (`renderInterview`) — на ней сверху кнопка
«Пройти пробное собеседование». Ещё ссылки: конец урока 6.4 (`m6l8`),
главная — строка рядом со ссылками на «Мои ошибки» и карту навыков, поиск
(`Find.places`).

Три экрана:

1. **Начало.** Что будет (3 SQL-задачи, 5 вопросов, 1 кейс, 45 минут, без
   подсказок), строка про урок 6.4, если он не пройден, история прошлых попыток
   (если есть), кнопка «Начать».
2. **Попытка.** Сверху — таймер обратного отсчёта и три вкладки «SQL 1 2 3 ·
   Вопросы · Кейс» с отметкой «есть ответ». Между вкладками можно ходить
   свободно. Внизу — «Завершить» с подтверждением. На нуле таймера попытка
   завершается сама.
   - SQL: условие, свёрнутая схема такси (`schema` урока `m6l8`), редактор
     (`mountEditor` + `CodeKit.setup` с таблицами такси), «Запустить» —
     таблица результата или текст ошибки. Вердикта нет.
   - Вопросы: пять вопросов `testQuestion` подряд, ответ выбирается без
     «Почему»; выбор можно поменять до завершения.
   - Кейс: условие и поле ответа (textarea).
3. **Отчёт.** Итог по частям и время. По каждой SQL-задаче — совпало или нет
   (`Check.sql` по последнему запущенному коду; не запускал — «нет ответа»),
   причина расхождения, эталонное решение и ссылка на урок `lesson`. По
   вопросам — верно или нет и «Почему», ссылка на урок. По кейсу — ответ
   ученика, эталон и чек-лист: ученик отмечает пункты, балл кейса = отмеченные.
   Внизу — «Пройти ещё раз» и таблица попыток.

## Попытка: выбор и состояние

- SQL — по одной задаче каждого уровня (`easy`, `mid`, `hard`), случайно
  (`shuffled`). Вопросы — 5 случайных из `quiz` уроков модулей 1–4 и 6 (как
  `ModuleTest.pick`; модуль 5 — машинное обучение, на собеседование junior
  аналитика не берём). Кейс — один из пула.
- Если в прошлой попытке выпадали те же задачи, повторы избегаются: из уровня
  берутся задачи, которых не было в последней попытке, пока такие есть.
- Черновик попытки (выбор, код по задачам, последний запущенный код, ответы,
  текст кейса, время старта `t0`) — в `sessionStorage` в try/catch. Перезагрузка
  вкладки продолжает попытку; таймер считается как `45 мин − (сейчас − t0)`,
  поэтому сон ноутбука и фоновые вкладки его не останавливают. Без
  `sessionStorage` попытка живёт до перезагрузки.
- Уход на другой хэш не завершает попытку: вернувшись на `#mock`, ученик
  видит её с тем же временем. Таймер снимается через `Router.cleanup`.
- Запрос к такси грузит базу через `Engine.sql(code)`; при открытии попытки
  база такси прогревается заранее (`Engine.sql("trips")`).

## Прогресс

Новый раздел `Store` `mock`: ключ — время старта (`t0`, число миллисекунд
строкой), значение `{sql, quiz, cas, casOf, mins, ids}`:
`sql` 0–3, `quiz` 0–5, `cas` — отмеченные пункты чек-листа, `casOf` — их
число, `mins` — минут от старта до завершения (не больше 45), `ids` — id SQL-задач и кейса.
Запись делается при завершении; отметки чек-листа после завершения обновляют `cas`.
`Store.merge` — режим «заполнять пустое» для `mock` (ключи-метки разных
устройств не пересекаются, импорт объединяет истории). Промахи в вопросах
записываются в повторение (`Review.record`), как в итоговом тесте модуля.

## Контент: `interview.js`

`window.MOCK = { sql: [...], cases: [...] }`, грузится лениво (`Lazy.mock`),
входит в `Offline.files` и в LAZY `build.py`.

SQL-задача: `{id, level, title, body, solution, expected: {columns, rows, ordered}, lesson}`.
Кейс: `{id, title, body, ref, check: [строки]}`.
`id` не меняются: на них ссылается история.

### Кейсы (4)

1. **`ekb-april`** — «Доля завершённых заказов в Екатеринбурге упала с 87,7% в
   марте до 71,7% в апреле (130 → 159 заказов). Как будете разбираться?»
   Эталон: данные и определения → разложить по статусам (no_driver 7,7% →
   18,9%) → по часам и тарифам → предложение (водители, наценка).
   Чек-лист: проверил данные и определение метрики; назвал знаменатель;
   разложил по статусам; разрезал по часу/тарифу; сравнил с другими городами;
   предложил следующий шаг с метрикой.
2. **`evening-surge`** — «Продакт хочет поднять вечернюю наценку на 10%. Как
   проверить, что это хорошая идея?» Эталон: гипотеза и метрика (выручка на
   заказ × доля завершённых), предохранители (отмены пассажиром, подача),
   эксперимент — по городам/дням (switchback), а не по пассажирам, из-за общего
   пула машин; длительность и мощность. Чек-лист — 6 пунктов.
3. **`check-up`** — «Средний чек вырос с 314,44 ₽ в марте до 334,73 ₽ в апреле
   (+6,5%). Это хорошо?» Эталон: эффект состава — доля поездок с наценкой
   17,1% → 25,0%, доля не-econom 32,2% → 35,6%; сравнить чек внутри тарифа;
   посмотреть объём и долю завершённых. Чек-лист — 5–6 пунктов.
4. **`dashboard`** — «Операционный менеджер просит дашборд на каждый день.
   Что на нём будет?» Эталон: главная метрика (доля завершённых), дерево (заказы
   → статусы → подача), разрезы город × час, пороги и алерты, частота
   обновления. Чек-лист — 5–6 пунктов.

## Движок

- `Mock` в `app.js` рядом с `ModuleTest`: `pick`, `draft` (sessionStorage),
  `mount` (вкладки), `finish`, `report`; `renderMock(app)` по образцу
  `renderSummary`; маршрут в `Pages.find`.
- `testQuestion` получает необязательный флаг «без пояснения» — остальные
  вызовы не меняются.
- Таймер — по образцу `mountTimer`, видимый, обратный.
- Стили: вкладки, таймер, отчёт; телефон 390 px и тёмная тема.
- `Store`: `EMPTY.mock`, ветка в `merge`.
