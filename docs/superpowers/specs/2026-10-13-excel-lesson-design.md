# Урок 6.5 «Excel и Google Таблицы на тестовом»

Дата: 2026-10-13. Этап 4 плана улучшений (раздел 6, строка «Excel / Google Sheets»).

## Зачем

Excel и Google Таблицы в курсе упоминаются только для сравнения: около 10 раз, и ни одного задания. При этом тестовые задания джунам часто присылают файлом xlsx, а в вакансиях «уверенный Excel» стоит рядом с SQL. Ученик к модулю 6 знает GROUP BY, JOIN и `pivot_table`, но не знает, как то же самое сделать сводной таблицей и ВПР, и спотыкается о мелочи табличных программ: разделитель `;`, русские имена функций, ВПР без точного совпадения.

Критерий успеха: ученик скачивает xlsx с данными «Дельта Маркета», подтягивает канал к заказам через ВПР или XLOOKUP, строит сводную, считает СУММЕСЛИМН и СЧЁТЕСЛИМН, получает те же числа, что SQL на той же базе, и вводит их на сайте. Сайт проверяет каждое число.

## Движок: вид урока `sheet` и поля для чисел

### Данные урока

```js
m6l7: {
  file: "delta-market.xlsx",          // ссылка «Скачать данные» над задачей
  fields: [
    { label: "Выручка оплаченных заказов из канала organic", unit: "₽",
      answer: 271926.54, tol: 1,      // допуск по модулю; по умолчанию 0,5
      hint: "Проверьте, что в сумму попали только строки со status = paid.",
      check: "SELECT ROUND(SUM(o.revenue), 2) FROM orders o JOIN users u USING(user_id) WHERE o.status = 'paid' AND u.channel = 'organic'" },
    …
  ],
  …   // theory, task, hints, solution, drills, quiz, cards, links — как у других уроков
}
```

- `unit: "%"` — ответ в процентах (47,3, а не 0,473); подпись поля показывает единицу.
- `check` — SQL на учебной базе, который даёт `answer`; нужен только скриптам проверки, ученику не показывается.

### Ввод и сверка

- Вместо редактора — список полей с подписью и единицей. Разбор ввода: убрать пробелы (обычные, неразрывные, узкие), `₽` и `%`, запятую считать десятичной точкой. «1842», «1 842», «1842,0», «1 842,00 ₽» — одно и то же. Не число — «Введите число: цифры, запятая или точка».
- Кнопка «Проверить» сверяет все поля: `|ввод − answer| ≤ tol`. Неверное поле помечается, под ним — его `hint`. Верные — галочкой ручкой, как в остальном курсе.
- Все поля верны — задача решена: та же отметка о прохождении, что у урока-разбора (`kind: "text"`), счётчик попыток тот же. Введённое сохраняется в `code[id]` строкой JSON (массив строк по полям) — новых разделов прогресса нет, перенос прогресса работает как раньше.
- «Показать решение» — как у остальных уроков, после первой попытки.

### Тренажёр

Задача тренажёра с `answer: "nums"` и своим `fields` — тот же компонент внутри задачи. Решённая отмечается в `drills` (`"урок:i"`), как остальные. `Drills.kind` возвращает `"nums"`.

### Файл xlsx

- `delta-market.xlsx` в корне сайта. Собирает `инструменты/mkxlsx.py` (openpyxl) из `data.js`: листы `orders`, `users`, `leads`; даты — настоящими датами Excel, суммы — числами, у `leads` — сырые строки как в базе (для чистки). Повторяемость: фиксированные даты создания в свойствах книги и у файлов внутри zip — тот же `data.js` даёт побайтно тот же xlsx.
- Офлайн: файл в `Offline.files`; в собранном `Тетрадь аналитика.html` — `data:`-ссылкой (build.py кладёт `window.FILES = {"delta-market.xlsx": "data:…"}`, app.js берёт ссылку оттуда, если она есть).
- Google Таблицы: в уроке — как открыть xlsx (Файл → Импорт или загрузка на Диск).

### Проверки

- `инструменты/checknums.js` (шаг в `ci.sh`): у урока и у каждой задачи `answer: "nums"` — `check` выполняется на `shop.db`, результат совпадает с `answer` в пределах `tol`; разметка полей (label, answer, hint, check). Ловит и опечатку в эталоне, и устаревшее число после правки данных.
- `checkdrills.js` считает задачи `nums` отдельной строкой и не гоняет их как SQL.
- Шаг `ci.sh`: xlsx пересобран (`mkxlsx.py` и `git diff --exit-code delta-market.xlsx`); в GitHub-проверку — `pip install openpyxl`.
- Разбор ввода — сценарии в `checknums.js` (вырезает функцию разбора из app.js, как `checkskills.js` вырезает `Skills`): «1 842,00 ₽», «1842.5», «47,3%», «abc», пустое поле.

## Содержание урока

### Теория

1. Зачем аналитику Excel, если есть SQL: тестовые в xlsx, выгрузки для заказчика, быстрые проверки.
2. Словарь перевода: фильтр и сортировка — WHERE и ORDER BY; сводная таблица — GROUP BY и `pivot_table`; ВПР / XLOOKUP (ПРОСМОТРX) — LEFT JOIN по ключу; СУММЕСЛИМН / СЧЁТЕСЛИМН / СРЗНАЧЕСЛИМН — агрегат с WHERE; условное форматирование — подсветка выбросов.
3. Ловушки: ВПР без `ЛОЖЬ`/0 в последнем аргументе ищет приблизительно и молча берёт не ту строку; ВПР смотрит только вправо (XLOOKUP — нет); русский Excel — русские имена и `;`, Google Таблицы — английские имена; даты и числа текстом (выравнивание по левому краю — признак); сводная не обновляется сама; дубли ключа в справочнике.
4. Как сдавать тестовое в xlsx: исходные данные отдельным листом, расчёты формулами, а не вставленными числами, вывод на первом листе.

### Задача

Мини-тестовое на 4–5 чисел по листам `orders` и `users`: выручка оплаченных заказов по каналу (ВПР канала к заказу + сводная), средний чек оплаченных, доля пользователей с оплаченным заказом. Опорные числа (SQL на `shop.db`): оплаченная выручка organic 271 926,54 ₽ (74 заказа), paid_search 141 330,95 ₽, email 122 017,95 ₽; средний чек оплаченных 3 457,30 ₽; купили 104 из 220. Окончательный набор полей — при написании урока.

### Тренажёр, quiz, карточки, ссылки

- 4–5 задач `nums`: СЧЁТЕСЛИМН по городу и платформе, СРЗНАЧЕСЛИМН, чистка `leads` (СЖПРОБЕЛЫ и разные написания статуса — сколько лидов закрыто), сводная с двумя измерениями.
- 6 вопросов (ВПР без ЛОЖЬ, `;` против `,`, сводная против формул, текст вместо числа), 6 карточек, 2–3 ссылки на справку Microsoft и Google.
- Числа только из запросов к `shop.db`; запросы — в `check`.
