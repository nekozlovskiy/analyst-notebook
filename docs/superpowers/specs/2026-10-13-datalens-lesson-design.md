# Урок 4.7 «BI на практике: дашборд в DataLens»

Дата: 2026-10-13. Этап 4 плана улучшений (раздел 6, строка «BI на практике»).

## Зачем

Главная страница курса пишет, что дашборд требуют примерно в 60% вакансий, а BI-инструмента в курсе нет: DataLens упомянут в текстах, но ни одного задания в нём. Урок 4.6 учит проектировать дашборд словами; собрать его руками ученик нигде не пробует.

Критерий успеха: ученик скачивает `app-journal.xlsx` с журналом приложения, загружает его в бесплатный Yandex DataLens (тариф Community, нужен Яндекс ID), связывает листы в датасете, собирает дашборд из пяти чартов и селектора, читает с него пять–шесть чисел и вводит на сайте. Сайт сверяет каждое число с запросом к той же базе.

## Решения владельца курса

- Работа — в настоящем DataLens, не тренажёр внутри курса.
- Данные — журнал приложения (`app_users`, `app_activity`, `app_orders`), те же, что в уроках 4.1–4.5.
- Место — модуль 4, сразу после 4.6 «Дашборд: что показывать».
- Проверка — числа с собранного дашборда в поля (механика урока 6.5 `m6l7`) и чек-лист самопроверки по принципам 4.6 без влияния на зачёт.
- Интерфейс DataLens показывается схемами SVG и точными названиями кнопок по документации, без скриншотов.
- Данные отдаются одним xlsx с тремя листами (вариант без правок движка).

## Проверенные факты о DataLens

Документация «Создание подключения к файлу» (yandex.cloud/ru/docs/datalens/operations/connection/create-file, обновлена 31.08.2026): подключение «Файлы» принимает CSV, TXT и xlsx; до 10 файлов в подключении, каждый лист Excel считается отдельным файлом; до 200 МБ на файл; превью — первые 30 строк. Тариф Community бесплатный, публичные ссылки на дашборд в нём есть.

## Дашборд из задачи

Пять чартов и селектор; каждый отрабатывает одну ловушку BI, которую ловит поле с числом.

| Чарт | Что показывает | Ловушка |
| --- | --- | --- |
| Индикатор «Выручка за период» | `SUM([revenue])` | — (точка входа, проверка, что данные загрузились целиком) |
| Линия «MAU по месяцам» | `COUNTD([user_id])` активности по месяцам | `COUNT` вместо `COUNTD`; группировка даты по дню вместо месяца |
| Столбцы «Выручка по каналам» | `SUM([revenue])` по `channel` | связь `app_orders` с `app_users` |
| Таблица «ARPU по каналам» | вычисляемое поле `SUM([revenue]) / COUNTD([user_id])` | inner-связь теряет неплативших и завышает ARPU; знаменатель — все пользователи канала |
| Линия «Доля платящих по месяцу регистрации» | доля пользователей с заказом среди зарегистрированных в месяце | среднее от средних |
| Селектор «Платформа» | android / ios / web | селектор не связан с частью чартов |

Датасет связывает листы по `user_id`: `app_users` — главный, к нему left-связью `app_orders` и `app_activity`. Если связь `app_activity` и `app_orders` в одном датасете размножает строки (декартово произведение по пользователю), урок использует два датасета: «пользователи + заказы» и «пользователи + активность». Это решается при реализации проверкой на `shop.db` того, что даст каждая схема, и записывается в теорию как одна из ловушек.

## Устройство урока

### Теория

1. Четыре объекта DataLens: подключение → датасет → чарт → дашборд; что хранит каждый и где чинить ошибку. **Схема 1** — цепочка объектов с примерами из урока.
2. Датасет: связь листов по `user_id`, inner против left (с числом, на сколько вырастает ARPU при inner), измерения и показатели, агрегации `COUNTD` / `SUM` / `AVG` с соответствием в SQL, вычисляемые поля.
3. Редактор чарта: зоны X, Y, Цвет, Фильтры, группировка даты. **Схема 2** — разметка окна чарта с подписями зон.
4. Дашборд: селекторы, связи между элементами, публичная ссылка; что нельзя публиковать на работе — данные компании по публичной ссылке видны всем.
5. Пять ловушек, у каждой число на базе урока: `COUNT` против `COUNTD`, inner-связь, среднее от средних, день вместо месяца, несвязанный селектор.

Пути меню — по документации Яндекса; в теории оговорка: интерфейс меняется, объекты и их порядок остаются.

### Основная задача

- Тикет от продакта: «соберите дашборд к планёрке», и 5–6 чисел для слайда. Примеры полей: MAU за конкретный месяц; выручка одного канала; ARPU канала при выбранной платформе; доля платящих в месяце регистрации. Окончательный список подбирается при реализации так, чтобы каждое число требовало своего чарта или селектора и хотя бы два поля ловили ловушки из таблицы выше.
- У каждого поля — `answer`, `tol`, `hint` (что проверить, если не совпало), `check` (SQL на `shop.db`). Формат — как у `m6l7`.
- `schema`: листы файла, ключ `user_id`, как начать — «Подключения → Создать подключение → Файлы → Загрузить файлы»; прямо сказано, что нужен Яндекс ID, обходного пути урок не предлагает.
- Три подсказки, эталон — пошаговый разбор с формулами вычисляемых полей.
- Под эталоном — чек-лист из 8–10 пунктов по принципам 4.6 (заголовок отвечает на вопрос, у доли рядом знаменатель, подписан период, не больше 6–7 чартов, селектор действует на все чарты и т. п.). Обычный список в HTML, без состояния.

### Тренажёр, квиз, карточки, ссылки

- Тренажёр: 5 разборов. Ответ числом (`answer: "nums"`) или выбором; сюжеты — расхождения дашборда с SQL («MAU на дашборде в N раз больше, чем в запросе — почему»). Каждое число посчитано на базе.
- Квиз — 6–8 вопросов, карточки — 6–8 терминов (подключение, датасет, измерение, показатель, `COUNTD`, вычисляемое поле, селектор, публичная ссылка).
- Ссылки — документация DataLens: подключение к файлу, датасеты, вычисляемые поля, селекторы, публикация.
