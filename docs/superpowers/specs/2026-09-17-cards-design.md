# Карточки «вопрос → ответ»: пилот на модуле 1

Дата: 2026-09-17. Ветка: `cards-pilot` (от `design-search-offline`).

## Зачем

Курс даёт теорию, задачи и самопроверку с вариантами ответа. Не хватает
вспоминания без подсказки: вопрос с вариантами проверяет узнавание, а на
собеседовании вариантов не дают. Карточка просит сначала ответить в голове
и только потом показывает ответ.

Это первая из пяти частей углублённого изучения. Порядок остальных:
«Мои ошибки», «Задачи вперемешку», «Пробное собеседование», «Глубже
в уроке». У каждой свой дизайн и план. Карточки идут первыми, потому что
дают данные для «Моих ошибок» и материал для пробного собеседования.

## Объём пилота

- Механика целиком: раздел в уроке, карточки в повторении на главной,
  клавиши, счётчик ошибок.
- Содержание только для модуля 1: 8 SQL-уроков, около 8 карточек на урок,
  всего около 65.
- Остальные пять модулей получают карточки отдельным шагом, после того как
  пользователь посмотрит пилот вживую и одобрит тон и глубину вопросов.
- Не входит: поиск по карточкам, отдельная страница-колода, карточки
  в модулях 2–6.

## Данные

### Формат в уроке

Поле `cards` в объекте урока в `content-mN.js`, рядом с `quiz`:

```js
cards: [
  { q: "Чем ROW_NUMBER отличается от RANK при равных значениях?",
    a: "RANK даёт одинаковый номер и пропускает следующий; ROW_NUMBER нумерует подряд." }
]
```

- `q` — вопрос, как его задали бы на собеседовании. Текст без разметки,
  кроме `<code>`.
- `a` — ответ: 1–3 предложения или несколько строк кода. Можно `<code>`
  и короткий `<pre><code>`.
- Одна мысль на карточку. Порядок — как в теории урока.
- Числа в ответах — только те, что уже проверены: встречаются в теории
  этого урока или в `ПРОГРЕСС.md`. Новых чисел карточки не вводят.
  Проверяет скрипт `инструменты/checkcards.js`.
- Урок без поля `cards` (или с пустым массивом) выглядит и работает
  как сейчас.

Поле описывается в шапке `content-core.js` рядом с `quiz`.

### Расписание

Карточки используют ту же корзину `review` в `Store` и ту же лестницу
`Review.STEPS` = 1/3/7/21 день, что и вопросы самопроверки.

- Ключ вопроса самопроверки не меняется: `m1l2:3`.
- Ключ карточки: `m1l2:c3` (буква `c` и номер карточки в массиве).
- `Review.items()` разбирает ключ и возвращает `kind: "quiz" | "card"`
  и номер. Записи с ключом, который не разбирается, или с номером, которого
  больше нет в уроке, пропускаются, как сейчас.
- «Вспомнил» — то же, что верный ответ, «не вспомнил» — то же, что
  неверный. Логика `Review.record` не меняется: первая оценка ставит на
  ступень 0 (завтра), дальше верный ответ поднимает на ступень, неверный
  возвращает на ступень 0, верный на последней ступени — выучено.
- Первая оценка в уроке ставит карточку в расписание. Повторные прогоны
  в уроке расписание не трогают (флаг `fromLesson`, как у самопроверки).
- `Review.record` возвращает `true`, если запись сделана, и `false`, если
  пропущена из-за `fromLesson`, — по этому колода в уроке выбирает текст
  итога.

Пример записи (значения синтетические):

```js
review: {
  "m1l2:3":  { step: 1, due: "2026-09-20" },            // вопрос, старая запись без miss
  "m1l2:c0": { step: 0, due: "2026-09-18", miss: 1 },   // карточка, один раз не вспомнил
  "m1l2:c4": { step: 3, done: true, miss: 0 }            // карточка выучена
}
```

### Счётчик ошибок `miss`

Задел для части «Мои ошибки». В запись расписания добавляется поле `miss`:
сколько раз ученик не вспомнил карточку или неверно ответил на вопрос.

- Растёт при каждой оценке «не вспомнил» или неверном ответе, которую
  `Review.record` действительно записал. Оценки, пропущенные из-за
  `fromLesson`, счётчик не трогают.
- Сохраняется при переходе на ступень и в записи `done: true`.
- У старых записей поля нет — это читается как 0.
- Работает одинаково для карточек и вопросов самопроверки.

### Перенос прогресса

`Store.merge` уже переносит корзину `review` (запись из файла кладётся,
если здесь пусто). Изменений не требуется.

## Интерфейс

### Компонент карточки

`Flash.card(box, card, meta, onRate)` рисует одну карточку в `box`:

- `meta` — строка над вопросом («3 из 8» в уроке; «Карточка 3 из 12,
  из урока 1.2 «Оконные функции»» в повторении).
- Вопрос, под ним кнопка «Показать ответ».
- После нажатия под вопросом за чертой проявляется ответ (анимация
  `ink-in`, других нет), кнопка «Показать ответ» уходит, появляются
  «Не вспомнил» и «Вспомнил». Фокус переходит на «Вспомнил».
- Нажатие оценки вызывает `onRate(ok)` один раз и блокирует кнопки.
- Область ответа — `aria-live="polite"`. Все контролы — настоящие `<button>`.
- Клавиши, когда фокус внутри карточки: пробел или Enter — показать ответ
  (если ответ ещё скрыт), ← — не вспомнил, → — вспомнил. После открытия
  пробел и Enter, как обычно у кнопок, нажимают кнопку в фокусе —
  «Вспомнил». Если фокус в поле ввода, клавиши не перехватываются.

Карточка — отдельный объект, поэтому по правилу коробок у неё рамка
(радиус контейнера 13px, у кнопок 7px). Цвета: акцент — фиолетовая ручка
на «Вспомнил» и «Показать ответ»; «Не вспомнил» — обычная кнопка, без
красного, потому что это оценка, а не состояние ошибки.

На ширине меньше 600px кнопки оценки делят ряд пополам, высота
не меньше 44px.

### Раздел в уроке

- Секция `#s-cards` «Карточки» между `#s-theory` и `#s-task`.
- Пункт «Карточки» в якорной навигации после «Теории».
- Подводка: «Не подглядывая в теорию: сначала ответьте в голове, потом
  откройте ответ и честно оцените себя. С завтрашнего дня карточки будут
  возвращаться в повторение на главной».
- Колода показывает карточки по одной в порядке массива. После оценки
  сразу открывается следующая карточка, фокус — на её «Показать ответ»
  (без прокрутки страницы).
- Итог колоды: «Вспомнили N из M.» и дальше одно из трёх:
  - первый прогон, хотя бы одна карточка встала в расписание — «Завтра
    карточки вернутся в повторение на главной»;
  - первый прогон, но все карточки уже были в расписании (урок открыли
    повторно) — «Эти карточки уже в расписании повторения, прогон его
    не сдвинул»;
  - прогон «ещё раз» — «Расписание повторения этот прогон не меняет».
- Под итогом кнопка: если хотя бы одна не вспомнена — «Ещё раз
  невспомненные: K», прогоняет только их; если все вспомнены — «Прогнать
  ещё раз», все карточки. Оценки этих прогонов расписание не трогают.
- План занятия: отдельную строку не добавляем — сетка плана держит
  5 колонок, у шести уроков модуля 1 уже 5 пунктов, и шестой уехал бы
  на новый ряд. Вместо этого в уроках модуля 1 строка теории становится
  «Теория и карточки: …», а её время растёт на 5 минут.
- При печати урока секция карточек скрывается: на бумаге от колоды
  осталась бы одна карточка с кнопками.

### Повторение на главной

- Очередь одна: `Review.due()` возвращает и вопросы, и карточки.
  За раз не больше `Review.LIMIT` = 20, порядок перемешан.
- Подводка считает по видам: «Сегодня 12: 5 вопросов и 7 карточек из
  пройденных уроков». Если в очереди один вид — упоминается только он
  («Сегодня 7 карточек из пройденных уроков»). Текст про «накопилось,
  сегодня возьмём N» сохраняется.
- `Review.step` для вопроса рисует варианты, как сейчас; для карточки
  вызывает `Flash.card` с подписью «Карточка i из N, из урока X «…»».
  После оценки показывается кнопка «Дальше» / «Закончить», как у вопроса.
- Итог: «Готово: верно R из N» — «вспомнил» считается верным.
- Загрузка модулей, фильтр удалённых вопросов и ошибка сети — как сейчас,
  фильтр проверяет `C.cards[i]` для карточек.

### Клавиши

В `Keys.list` добавляется строка: «Пробел, ←, →» — «Показать ответ,
не вспомнил, вспомнил», пояснение «в карточках».

Автотестов в проекте нет. Проверка в браузере на `course-dev`
(`инструменты/devserver.py`, порт 8779):

   после первой оценки в `da.state.v1.review` есть `m1l2:c0` с `due`
   на завтра; `miss` = 1 после «не вспомнил»; повторный прогон в уроке
   запись не меняет; итог и кнопка «Ещё раз» работают.
2. Урок модуля 2: без секции «Карточки» и без пункта навигации, остальное
   как было.
3. Главная: даты в `review` сдвинуты на вчера — очередь смешанная,
   подводка считает по видам, лимит 20 соблюдён, карточка оценивается,
   итог верный, после оценки ступень выросла.
4. Совместимость: состояние со старыми ключами `m1l2:3` без `miss`
   загружается, повторение работает, `miss` появляется после ошибки.
   Выгрузка и загрузка прогресса файлом переносит записи карточек.
5. Клавиши: пробел, ←, → внутри карточки; в поле заметок не перехватываются;
   строка в окне `?`.
6. Ширина 375px и тёмная тема — скриншоты.
7. Текст: `node инструменты/checkcards.js --require m1` — формат, длина,
   разрешённые теги, посторонние символы, у каждого урока модуля 1 от 6
   до 12 карточек, каждое число в `a` найдено в теории урока или
   в `ПРОГРЕСС.md`.
8. Сборка: `python3 build.py`, файл `Тетрадь аналитика.html` открыт
   с диска — карточки работают.
