Дата: 25.09.2026. Этап 3 плана улучшений (`docs/ПЛАН-УЛУЧШЕНИЙ.md`), пункт «15 SVG-схем первой очереди». Эта спецификация — про общий механизм схем и первые четыре схемы модуля 1. Остальные одиннадцать выкладываются следующими порциями по ходу курса тем же механизмом, каждая порция — своя ветка и PR без новой спецификации.

## Зачем

В 42 уроках нет ни одного рисунка: JOIN, окна, когорты объясняются только текстом и таблицами. Ученик приходит с нуля (не знает Excel и программирования) и учится в том числе с телефона. Схема должна за несколько секунд показать механизм, который текст описывает абзацем.

Успех: у ученика на телефоне и на компьютере, в светлой и тёмной теме, схема читается без увеличения, числа на ней совпадают с базой курса и с текстом урока.

## Решения пользователя (25.09.2026)

- Начать этап 3 со схем; выкладывать по ходу курса порциями, первая — SQL.
- Стиль A «Тетрадь»: тонкие линии без заливки, фиолетовая ручка только на том, куда смотреть, пояснение почерком наставника внутри схемы.
- Телефон — вариант B: каждая схема рисуется сразу узкой (под 320 px), на компьютере стоит по центру не шире 520 px. Не сжимать широкую и не открывать по нажатию.
- Хранение — вариант 1: готовые SVG в файле модуля, числа считает скрипт по базе.

## Первая порция

| id | Урок | Место в теории | Что показывает |
| --- | --- | --- | --- |
| `sql-order` | m1l1 (1.2 JOIN) | раздел «Порядок выполнения запроса» | Порядок записи запроса слева и порядок выполнения справа: FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT (с окнами) → ORDER BY → LIMIT. Стрелки ручкой соединяют одно и то же слово в двух колонках. Реплика: «псевдоним из SELECT ещё не существует в WHERE». |
| `join-rows` | m1l1 (1.2 JOIN) | раздел «Ловушка первая: строки размножаются» | Слева `users` (2 строки), справа `orders` (3 строки), связи ручкой, ниже результат JOIN на 3 строки; точка ручкой у пользователя с двумя заказами. Реплика: «у N-го два заказа — две строки». Строки — настоящие из базы: пользователь ровно с двумя заказами (любого статуса — JOIN в уроке без фильтра) и пользователь с одним. |
| `window-frame` | m1l2 (1.3 Окна) | раздел «Рамка окна» | Заказы двух пользователей по дате, разделённые на окна `PARTITION BY user_id` (тонкая линия между окнами, подпись «окно»). Столбец «накопительно» = `SUM(revenue) OVER (PARTITION BY user_id ORDER BY order_date)`. У одной строки скобкой ручкой показана рамка «от начала окна до текущей строки». Реплика: «сумма начинается заново в каждом окне». Пользователи — с 3–4 оплаченными заказами. |
| `cohort-triangle` | m1l6 (1.6 Даты и когорты) | раздел «Когорта: что это такое на самом деле», после таблицы «Как читать когортную таблицу» | Когорты по месяцу регистрации (строки, январь–июнь) × месяцы жизни 0…5 (столбцы); в ячейке — доля когорты, купившей хотя бы раз к концу этого месяца жизни, в процентах. Пустой нижний правый угол — месяцы, которые когорта ещё не прожила целиком: заказы в базе по 11.09.2024, поэтому последний полный месяц — август (регистрации идут до 29.06.2024). Он и даёт форму треугольника. Реплика: «у свежих когорт хвоста ещё нет — это не падение». |

Числа для `join-rows`, `window-frame`, `cohort-triangle` берутся из `инструменты/shop.db` (та же база, что в курсе) и должны совпасть с тем, что ученик получит своим запросом.

## Устройство

### Хранение и вставка

- Схемы модуля лежат в его файле `content-mN.js` блоком между метками `/* FIGS:BEGIN */` и `/* FIGS:END */`: `window.FIGS = window.FIGS || {}; window.FIGS["join-rows"] = '<svg …>…</svg>';`. Грузятся вместе с уроками модуля (`Lazy.content`), отдельных запросов нет; `build.py` включает их в офлайн-файл без изменений.
- В теории урока место схемы: `<figure class="fig" data-fig="join-rows"><figcaption>Рис. JOIN соединяет строки — и размножает их</figcaption></figure>`.
- `Figs.mount(root)` в `app.js` вставляет SVG перед `figcaption` каждого `figure[data-fig]` внутри `root`. Вызывается после отрисовки теории в `renderLesson` (конспект модуля теорию не показывает, там схем нет). Если схемы с таким id нет — `figure` убирается целиком, в консоль `console.warn`: ученик не видит пустую рамку.

### Стиль (CSS в `styles.css`, раздел «Схемы»)

- `figure.fig`: по центру, `max-width: 520px`, отступы как у `.example`; `figcaption` — `var(--sans)` 13 px, `var(--ink-3)`.
- SVG без собственных цветов: только классы, цвета из токенов темы, поэтому тёмная тема работает без второй версии.
  - `.f-box` — рамка таблицы/блока: без заливки, `var(--rule-hard)`, 1 px, скругление 5.
  - `.f-row` — линия между строками: `var(--rule)`, 0.8 px.
  - `.f-hd` — заголовок таблицы: `var(--sans)` 600, `var(--ink-2)`.
  - `.f-sub` — подпись столбцов: `var(--sans)`, `var(--ink-3)`.
  - `.f-t` — данные: `var(--mono)`, `var(--ink)`.
  - `.f-pen` (линии) / `.f-pen-fill` (точки, скобки) — ручка `var(--pen)`, 1.4 px.
  - `.f-note` — реплика наставника: `var(--hand)`, `var(--pen)`.
  - `.f-tint` — единственная допустимая заливка (ячейки когорт): `var(--pen)` с `fill-opacity` от 0.06 до 0.3 по величине.
- Размер: `viewBox` шириной не больше 340; шрифт данных 12.5, подписей 10.5–12.5, реплики 15. На экране 360 px это 12–13 px без масштабирования.

### Доступность

- `<svg role="img" aria-labelledby="…">` с `<title>` (что изображено) и `<desc>` (ключевой вывод словами, с числами). Текст схемы остаётся текстом (`<text>`), не кривыми, — его находит поиск по странице и читает диктор.
- Никакой анимации.

### Генерация: `инструменты/figs.py`

- Один скрипт строит все схемы: для каждой — функция, которая читает нужные строки из `shop.db` (sqlite3, стандартная библиотека) и собирает SVG из небольших помощников (`table(x, y, title, cols, rows)`, `link(a, b)`, `note(x, y, text)`, `bracket(…)`).
- `sql-order` не требует данных, но строится тем же скриптом, чтобы стиль был один.
- Запуск `python3 инструменты/figs.py m1` переписывает блок `FIGS:BEGIN…END` в `content-m1.js`; повторный запуск без изменений данных даёт тот же текст (детерминированно, без случайностей).
- Выбор строк детерминирован: например, для `join-rows` — пользователь с минимальным `user_id` ровно с двумя заказами и следующий за ним пользователь ровно с одним.

### Проверка: `инструменты/checkfigs.js`

Падает с понятным сообщением, если:
- в теории есть `data-fig`, для которого нет `FIGS[id]`, или схема в `FIGS` нигде не используется;
- у схемы нет `role="img"`, `<title>` или `<desc>`;
- ширина `viewBox` больше 340;
- в SVG есть цвет, заданный напрямую (`#…`, `rgb(`, `fill="black"` и т. п.) — всё должно идти через классы.

Прогоняется вместе с `checkdrills.js`, `checkcards.js`, `checkterms.js` перед каждой выкладкой.
